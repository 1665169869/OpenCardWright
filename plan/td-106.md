# TD-106 最大发卡数 2/5/10 对安装卡字节的影响

**优先级** P1 · **状态** 已完成 · **来源** US-1106-2 · **模块** 发卡与卡片

**为什么做**：安装卡页2 固定为 `46 F2 00 01`，其中 `00 01` 的语义一直没确认（技术规格 §5.3 推测可能是楼栋 / 楼层 / 版本）。现场怀疑原厂软件的「最大发卡数」可能被写进安装卡；若成立，现在「所有房间统一照抄 `46F20001`」的做法在改过发卡上限的锁上可能不完整。

**现状**【核实】：
- `sdk/PMSLockSDK.cs:266` `BuildInstall`：页1 = `5B EC ((序号 << 4) | 0x0C) (序号 >> 4)`，页2 固定 `46 F2 00 01`，**不含卡号**。
- `docs/TEMIC门锁卡技术规格.md` §5.3「安装卡说明」：201 / 259 / 220 三个房号的页2 都是 `46F20001`；`00 01` 语义未确认，现网只有 1 栋 1 层，观测不到楼栋 / 楼层差异。
- `data/NacreHis.json` 导出里没有「最大发卡数」字段（全表搜「发卡数」只命中「发卡记录」；`max` 相关字段是 `GD_MAX_SC` 等，与门锁发卡上限无关）。原厂软件的「最大发卡数」存在哪里（锁内参数 / 软件设置 / 别的表）未确认。
- 本产品的 `room.max_cards`（`app/src-tauri/src/commands.rs:1075`）只是数据库里的业务上限，**不写卡**。

**改动点（原厂软件上的对照实验，无代码改动）**
1. 选**同一间测试房 / 同一把测试锁**，在原厂软件里把「最大发卡数」设为 2，发一张安装卡；再依次设为 5、10，各发一张安装卡。
2. 三张卡都用读卡器读出 28 字节原文，记录：设置值、房号、锁内序号、页1、页2、发卡时刻。
3. 比较三组的页1 / 页2：若完全相同，说明最大发卡数不写入安装卡；若不同，定位到具体字节并判断是否与 2 / 5 / 10 单调相关。
4. 如果原厂软件不允许同一房间重复发安装卡，改用三间**序号连续、房型相同**的测试房，分别设 2 / 5 / 10；比较时排除「序号不同导致的页1 差异」，只看页2 与页1 的低 4 位。
5. 若发现字段变化，登记证据后再评估是否更新 `sdk/PMSLockSDK.cs` 的 `BuildInstall` 与 selftest 向量 —— **改 `sdk/` 需用户拍板**（AGENTS §9 默认禁止产品侧改 SDK）。
