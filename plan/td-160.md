# TD-160 有效卡口径与同号卡的真机验证

**优先级** P1 · **状态** 待办 · **来源** US-1106-50 · **模块** 房间与预订

**为什么做**：TD-121 把「有效卡」从「按卡号去重」改成「按张计数」，并让无卡退房按记录逐条退。
这些**只跑了单元测试**，TD-121 正文末尾就写着「真机验证待做」，但一直没进待办列表，容易整批漏掉。
真机不验证，现场可能表现成「房间卡片显示 2 张、实际退房只退掉 1 张」。

**现状**【已实现，待真机】：
> 2026-11-10 复核：代码侧三项口径均已确认（`count_active_cards` / `ROOM_SELECT` 按张计数、
> 抽屉与无卡退房按 `issuance.id` 逐条列、无卡退房按卡号去重后逐张退并回写 `remaining`），
> 只剩下面三项真机验证，代码无需改动。
- `count_active_cards` 与 `ROOM_SELECT` 的内联 `active_cards` 都用 `COUNT(*)`（同号两张算 2 张）
- 抽屉与无卡退房弹窗按 `issuance.id` 逐条列（同号两张各占一行，弹窗有「同号卡会一起退房」提示）
- 无卡退房按卡号**去重**后逐张调 `checkout_card`（同号只调一次），剩余张数用后端返回的 `remaining`

**待验证（三项，一次做完）**
1. **两张同号卡都能开门**：按 TD-127 复用首卡卡号发两张同号卡，分别刷门，两张都能开
2. **退房一起失效**：用其中一张走持卡退房，另一张同号卡应立刻失效
3. **无卡退房不碰读卡器**：手不碰读卡器，右键「无卡退房」勾选提交，应成功且审计里 `erased=0`

**验收标准**
- [ ] 三项都在真锁 + 真读卡器上通过
- [ ] 房间卡片显示的「有效卡 N 张」与实际能开的卡数一致
- [ ] 无卡退房不再报「串口打开失败 / 读卡失败」
- [ ] 若不符，区分是计数口径问题还是退房 SQL 问题
