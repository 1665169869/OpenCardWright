# TD-128 预定房发卡两个 bug 修复 + 记录页默认 20 条

**优先级** P1 · **状态** 已完成 · **来源** US-1106-30 · **模块** 发卡与卡片

**为什么做**：用户实测反馈三点——① 预定房**未填姓名**时，发卡前「是否给预定客人发卡」对话框的确定按钮被禁用，流程被卡住；② 预定房**开卡后预定信息不消除**（日历仍显示预定色块、房号列仍是「预定」tag）；③ 记录页默认每页 50 条偏多，要求 **20 条/页**。

**现状**【核实】：
- `RoomManager.tsx` 确认框主按钮 `disabled={!issueConfirm.res.guestName}`——无姓名预定直接禁用，只剩「不是，手动填写」；
- `reservation.status` 只有 `booked` / `cancelled`（schema CHECK），`issue_guest` 成功后只同步房态（TD-115），**不动预定**——`list_reservations` 只返回 `booked`，日历色块与「预定」tag 一直挂着；
- `Logs.tsx` 三个 tab 的 `pageSize` 初值都是 50。

**改动点**
1. **Bug 1**：去掉主按钮 `disabled`；无姓名时按钮文案改「是，继续发卡（预定未填姓名）」，提示文案同步（`confirmIssue(true)` 无姓名本就 `setIssueGuest(null)` 走手动填写）。
2. **Bug 2**：`reservation` 状态加 **`checked_in`（已入住）**——schema v9：`schema.sql` CHECK 加枚举 + `apply_v9`（SQLite 不能改 CHECK，建 `reservation_new` 全量迁数据再换名，按 `sqlite_master` DDL 探测幂等）+ `SCHEMA_VERSION` 8→9；新增 `check_in_reservations(conn, room_no, today)`（口径 `check_in <= today < check_out`）与 `local_today(conn)`；`issue_guest` 成功分支（房态同步后）调用——**发卡即消除**覆盖今天的有效预定。日历 / 房号列 / 改期弹窗入口都基于 `booked` 过滤，`checked_in` 自然不可见、不可改。
3. **记录页**：三个 tab 默认 `pageSize` 50 → **20**（分页器仍可手动改 20/50/100/200）。

**验收标准**
- [x] 无姓名预定发卡：确认框主按钮可点，发卡流程不中断
- [x] 预定房开卡后：日历预定色块消失、房号列「预定」tag 变「入住」，再发第二张卡不再弹确认
- [x] 记录页三个 tab 默认每页 20 条
- [x] `cargo test --workspace` **120 项全绿**（含 `check_in_reservations_marks_tonight_only` 与 v9 迁移幂等）；`pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：`checked_in` 的旧数据不回溯（历史已发卡但预定仍 booked 的记录，等该房下次发卡时被本次逻辑覆盖标记）；日历数据源只取 `booked`，故「已入住」预定不在界面显示（记录仍在库，可审计）。
**待拍板**：已定（2026-11-07）——预定消除方式用「新增已入住状态」，非复用取消。
