# TD-132 排查「正式包带默认数据库」（结论：包内无库）

**优先级** P2 · **状态** 已完成 · **来源** US-1106-34 · **模块** 工程与发布

**为什么做**：用户看到正式版里有 30 个房间（含房号/房型），怀疑安装包把默认数据库一起打进去了。

**排查结论（三条证据）**
1. `tauri.conf.json` 的 `bundle.resources` 只有 `["resources/sdk/**/*"]`——NSIS 包只装 exe + SDK 运行时，
   **不含 `.db`、不含 `data/*.json`**；
2. 示例房间导入代码（`main.rs` 里读 `data/NacreHis.json` 的 `Kf_fh`）整段在
   `#[cfg(debug_assertions)]` 内，release 构建不编译；
3. release 产物 `grep NacreHis` 只命中一处错误文案「原门锁软件占着串口，先关掉它（NacreHis.exe）」，
   没有 `data/NacreHis.json` 路径字符串。

**真因**：本机 `%PROGRAMDATA%\OpenCardWright\` 里有 11-05 调试期留下的
`opencardwright.db`（163 KB，含 30 个示例房间）+ `.before-kffh.bak` / `.pre-v3.bak` / `.reset-bak` 等
调试备份；正式版读同一个位置，于是「看起来像安装包自带」。

**处理（已执行，用户拍板「备份后清空」）**
- 应用关闭后，把 `opencardwright.db*` 共 11 个文件整体移到
  `%PROGRAMDATA%\OpenCardWright\backups\parked-20261107\`；
- 重启 release 版 → 新建空库（主库 4 KB，无房间数据），确认 dev 导入逻辑确实不在发布版里；
- 用户明确**不需要**「清空数据库」按钮，未加功能入口。

**验收标准**
- [x] 安装包/资源清单里无数据库文件
- [x] release 构建不含示例数据导入（cfg 门 + 字符串检查）
- [x] 本机历史库已备份、主目录清空，重启后为空库

**依赖 / 风险**：别人若把本机 `%PROGRAMDATA%` 一起拷走，会带上旧库；交付给客户时保持干净机器即可。
**待拍板**：无（用户已拍板：备份后清空、不加清空功能）
