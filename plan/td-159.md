# TD-159 app 启动时没有自动检测 COM 口

**优先级** P1 · **状态** 已完成 · **来源** US-1106-49 · **模块** 设备与串口

> **修复（2026-11-08）**：三处根因——
> ① `probe_ports` 原为 `Level::Login`，登录页根本调不到 → 改为 **Public**（矩阵计数 35/28/7）并去掉函数体里的 `require_login`；
> ② `App.tsx` 的 `refreshInfo()` 挂在 `loggedIn` 条件里，登录页永远不触发探测 → 改为**挂载即跑**，登录状态变化后再刷一次；
> ③ 顶栏四态补全：`deviceOk === null` 现在显示「等待探测…」，不再把「还没结果」误报成绿色「设备就绪」。
> 验证：`cargo test --workspace` 126 项全绿、`tsc --noEmit` 通过。

**为什么做**：用户反馈「app 启动时没有自动检测 COM 口」——启动后设备状态不是「设备就绪」，
要手动进设置页选串口。这违背 TD-138（启动设备探测）的目标，属于功能未达预期或回归。

**现状**【待核实】：TD-138 做过「启动时后台 `probePorts()`」，顶栏有四态
（探测设备中 / 模拟设备 / 未探测到设备 / 设备就绪）。当前表现为没自动检测，可能原因：
1. `probePorts()` 只在 `appInfo()` 之后跑，而 `App.tsx` 的调用链近期被改过（2026-11-08 删水位时动过 `refreshInfo` 相关代码）；
2. `probePorts()` 失败但没有把 `deviceOk` 置为 `false`，顶栏停在初始态；
3. 串口被占用（`NacreHis.exe`）或驱动未就绪，但**没有把原因显示出来**。

**改动方向**
1. 启动时**先**跑一次端口探测（可并行于 `appInfo`），把结果写进 `deviceOk`；
2. 顶栏在探测期间显示加载态，探测完成给出明确结论（就绪 / 未探测到 + 原因）；
3. 失败原因区分：串口被占用、驱动指纹不符、无读卡器、权限不足；
4. `OCW_SIM=1` 时必须显示「模拟设备」，不能被判定为「未探测到」。

**验收标准**
- [ ] 冷启动 2 秒内顶栏给出「设备就绪」或**具体**失败原因
- [ ] 不需要用户手动进设置页选串口
- [ ] 模拟设备模式显示「模拟设备」
- [ ] 断开读卡器后重启，能明确提示「未探测到设备（原因）」
