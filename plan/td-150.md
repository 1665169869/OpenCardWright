# TD-150 CardNo 改为时间戳编码（日5 + 时5 + 序号6）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-44 · **模块** 发卡与卡片

**为什么做**：原厂的「卡号」不是计数器，而是**紧凑时间戳**——`日(5位) + 时(5位) + 小时内序号(6位)`
正好 16 位。所以读卡器/原厂软件能从卡号还原真实发卡时间。我们的 `CardNo.state` 是纯递增，
解出来是「日 4 / 时 12 / 序号 6」这类假值，所以永远显示 2026-11-04。

**现状**【实测，6 组样本，见 `docs/TEMIC门锁卡技术规格.md` §4.2】

```
卡号高字节 = (日 << 3) | (时 >> 2)
卡号低字节 = ((时 & 3) << 6) | 小时内序号(0..63)

解码：日 = 高字节 >> 3
      时 = (高字节 & 0x07) * 4 + (低字节 >> 6)
      序号 = 低字节 & 0x3F
```

验证样本：`0x345B` → 日 11 / 时 12 / 序号 52；`0x345A` → 日 11 / 时 8 / 序号 52；
`0x2381` → 日 4 / 时 14 / 序号 1。全部与 RWCardDemo 读数一致。

**改动方向**
1. `CardNoStore.Next()` 改为按上面的公式生成卡号（输入：发卡时刻 + 该小时内已发张数）；
2. **保持全局单调递增**（锁的水位要求）：「日 + 时」本身递增，同小时内序号递增即可满足；
3. 跨小时/跨日时校验新值必须大于当前 `CardNo.state`，否则拒绝发卡并提示（避免倒退）；
4. `PMSLockCard.exe` 增加 `--at "YYYY-MM-DD HH"` 与 `--seq N`（**1–63，本小时第 n 张**），便于离线构包与 selftest 复核。
5. **进位后小时不回退**（2026-11-08 修正）：满 63 张进位到下一小时后，该「未来小时」成为下一次计算的基准；
   下一张接着在进位后的小时里发（第 65 张 = 15点第 2 张），不会退回当前小时。
   原实现用 `now > 卡号小时` 比较，第 65 张会算回当前小时——已修，并有 selftest 回归用例。

**验收标准**
- [ ] 按公式生成的卡号，RWCardDemo 读出的时间与发卡时刻一致（日/时/序号三项）
- [ ] 连续发 5 张卡，卡号严格递增
- [ ] 跨小时发卡，序号从 0 重新开始且卡号仍递增
- [ ] `selftest` 27 条向量仍全绿（现有向量的卡号需要同步重算或保留旧规则做兼容）

**依赖 / 风险**：
- **切换点风险最大**：新规则算出的卡号如果**小于**存量卡号，锁会当「旧卡」拒绝（需配复位卡或等自然增长到位）；
- 已有发卡记录（`issuance` 表）里的卡号是旧规则，混用后「按卡号排序」的历史会失真；
- 影响 27 条黄金向量（向量里写死了卡号）。

**切换流程（已定 2026-11-08：刷复位卡后统一切换）**
1. 停机窗口内，对**每个房间的锁各刷一次复位卡**（清空该房卡记录、水位归零）；刷完立刻收回复位卡（它不设防）
2. 切换后首次发卡，`CardNo.state` 会跳到 5 位数（如 `0x43C0`），属正常
3. 若 `Next()` 抛「卡号倒退」，说明该房还没刷复位卡 —— 补刷即可
4. 过渡期**不要混发旧卡**：旧卡号可能大于新卡号，锁会把它当成更新的卡
5. 已发出的旧卡在新规则下仍然可用，但读卡器解出的「发卡时间」会失真（旧号不是时间戳）
