# TD-221 入住记录与日历改按登记单展示

**优先级** P1 · **状态** 已完成 · **来源** US-1111-1 · **模块** 房间与预订

**为什么做**：TD-220 把身份信息搬到独立登记单之后，展示层还停留在「发卡记录 + 单人」：
入住记录页是 `guest_only` 的发卡列表，日历只显示 `issuance.guest_name`。
用户要求日历优先显示**首个登记人**，点详情能看到**全部同行人**（下拉列表逐个查看）。

## 现状（登记时）

- 入住记录页 `CheckinTab`：`listIssuances({ guestOnly: true })`，与发卡记录同一份数据。
- CSV 导出：`export_issuances_csv(guest_only=true)`。
- 日历：`list_guest_stays` 的 `guest_name` 取 `issuance.guest_name`。
- 数据库里没有任何登记单。

## 改动点（全部完成）

- [x] **历史迁移（v14）**：每条 `guest_name` / `guest_id_number` 非空的 `issuance` 生成一张 `closed` 登记单
      （`check_in_at = created_at`、`check_out_at = checked_out_at`、`note = 历史数据迁移（TD-221）`）
      + 一条 `seq = 1` 住客，并回填 `issuance.checkin_id`；幂等靠 `checkin_id IS NULL`。
      单测 `v14_migrates_legacy_guest_identity_once`。
- [x] **入住记录页**：改 `listCheckins`，一单一行（房号 / 首位登记人 / 人数 / 入住时间 / 退房时间 / 状态 / 备注），
      详情弹窗用 `getCheckin` 列出全部住客。
- [x] **CSV 导出**：新增 `export_checkins_csv`（管理员，`checkins_to_csv`，一单×一住客一行，
      文件名「入住登记-<时间戳>.csv」，`CheckinExportRow` + `export_checkins` LEFT JOIN 查询）。
- [x] **日历**：`list_guest_stays` 的 `guest_name` 改为 `COALESCE(首个登记人, issuance.guest_name)`，
      新增 `checkinId` / `guestCount`；色块显示「张三」或「张三 等 N 人」；
      点详情按 `checkinId` 加载住客，下拉切换查看性别/证件/民族/出生/有效期/签发机关/住址。
- [x] **旧字段**：`issuance.guest_*` 不再写入，保留只读；`update_guest_identity` 标注为历史接口。
