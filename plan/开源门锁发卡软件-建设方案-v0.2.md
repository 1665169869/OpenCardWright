## 1. 目标与验收标准

1. 干净 Win11 上 5 分钟装完，发出一张**实测能开门**的日租卡。
2. UI 内"自检"显示 **27 通过 / 0 失败**（转发 SDK `selftest`），构建流水线同样以它做门禁。
3. 读卡页：读原厂发的卡（DB 无记录）时**卡片数据完整显示**，仅出现"未查到发卡记录"提示条。
4. 新增一间房：分配序号 → 制作安装卡 → 在锁上刷一次即完成绑定（真机验证一次）。
5. 断网全流程可用；发卡端到端 P95 ≤ 3s（实测入档）。
6. 管理卡需二次确认 + admin 角色，审计不可删。

## 2. 硬约束

| 约束 | 事实 | 后果 |
|---|---|---|
| 驱动位数 | `LC32RFRW.dll` 为 PE32 x86 | 只有子进程需 32 位；主程序 x64 |
| .NET 依赖 | `PMSLockCard.exe` 为 net40 x86 | Win10/11 自带 .NET FW 4.8；启动预检 `Release ≥ 528040` |

| 卡密码 | `12000206`，必须 `config_parameter(0)` | 由 SDK 内部处理 |

## 3. 架构

```
构建期： ../sdk/*.cs ──csc──▶ resources/sdk/{PMSLockCard.exe, PMSLockSDK.dll, ini}
        ../sdk/IOServer/LC2000/*.dll ──copy──▶ resources/sdk/IOServer/LC2000/

运行期：
  WebView2(React) ──IPC──▶ OCW.exe(x64): commands / app / CliBackend / rusqlite
                              └─Process.Start──▶ runtime\PMSLockCard.exe(x86) ──▶ LC32RFRW.dll
```

- 首次运行把 `resources/sdk` 复制到 `%ProgramData%\OpenCardWright\runtime\`，只跑副本（`CardNo.state` 需可写）。
- 单实例互斥；设备调用串行化；单片超时 15s，超时杀进程树，**不自动重试**。

## 4. 构建流水线

`scripts/build-sdk.ps1`（由 Tauri `beforeBuildCommand` 调用）：

1. `csc /target:library /platform:x86 /out:resources/sdk/PMSLockSDK.dll PMSLockSDK.cs`
2. `csc /target:exe /platform:x86 /out:resources/sdk/PMSLockCard.exe /r:PMSLockSDK.dll PMSLockCard.cs`
3. 复制 `LockCard.ini`、`IOServer\LC2000\*`；**不复制仓库里的 `CardNo.state`**
4. **门禁**：跑 `PMSLockCard.exe selftest`，退出码非 0 即构建失败（纯字节，无需硬件）
5. 生成 `resources/sdk/manifest.json`：各文件与驱动 SHA-256、构建时间
6. 开关 `-BundleDriver:$false` 可改为"首启导入驱动"（默认打包）

## 5. 设备通道契约

`PMSLockCard.exe <verb> --ini <abs> --port <n> --dir <abs> --json`

| 场景 | 命令 |
|---|---|
| 读卡 | `read --json` |
| 日租 / 钟点 | `issue --room <房号> --days <n>` / `--hours <n>` `--json` |
| 总控 | `issue --type master [--days n｜--hours n] --json` |
| 复位 / 清除 | `issue --type reset｜clear --json` |
| **安装** | `issue --type install --room <房号> --json` |
| 退房钟点 | `issue --type checkout --hour <0-23> --json` |
| 校时 | `issue --type timesync [--room HH:MM] --json` |
| 原始直写 | `issue --type raw --p1 <8hex> --p2 <8hex> --json` |
| 自检 / 端口 | `selftest` / `ports`（文本） |

成功 `{"ok":true,"card":{kind,room,roomIndex,days,hours,cardNo,raw}}`；失败 `{"ok":false,"error":{code,msg}}`；退出码 0–7。
解析：优先 JSON；失败则以退出码为准，stderr 进诊断日志；`selftest`/`ports` 正则抓取，**抓不到视为异常，不得当作通过**。

**退出码**：0 成功 / 1 参数 / 2 驱动或串口 / 3 无卡 / 4 写失败 / 5 回读校验失败 / 6 卡号无效 / 7 不支持。

## 6. 数据与卡号治理

**表**：`room`（`room_no` PK、`room_index` UQ 0–255、building、floor、room_type、active、install_card_at、created_at）、`issuance`（`id`、`uuid`、`room_no`、`kind`、`days`、`hours`、`card_no` **索引**、`raw_hex`、`operator_id`、`reader_id`、`result`、`error_code`、`idempotency_key` UQ、`created_at`、`duration_ms`）、`operator`、`audit_log`、`device`、`setting`、`schema_version`。

**卡号分配器 = `CardNo.state`（CLI 自增），OCW 不自行发号**

1. 默认不传 `--serial`，从返回 JSON 取 `cardNo` 落库。
2. 仅"补卡/重发"允许 admin 指定 `--serial`，需填原因 + 审计；之后把 `CardNo.state` 抬到 `max(当前, 指定值)`。
3. 启动比对：`max(issuance.card_no)` > `CardNo.state` 时黄条告警，不自动改写，提供 admin"同步水位"。
4. **起始卡号保护**：安装包不带 `CardNo.state`；首启向导要求输入起始卡号（默认 `0x2403`），文案写明"必须大于该楼锁内已见过的最大卡号"；导入已有 `CardNo.state` 时沿用。
5. 水位 `≥0xE000` 黄条；`≥0xFF00` 阻断发客卡；`0xFFFF` 不回绕，跳"复位作业向导"。

## 7. 功能与界面

| # | 界面 | 要点 |
|---|---|---|
| 1 | 值班台 | 设备状态灯、卡号水位、今日发卡数、最近 10 条 |
| 2 | 发卡 | 选房 → 选时长 → 确认 → 进度 → 结果 + 打印制卡单 |
| 3 | 读卡 | 见下 |
| 4 | 管理卡 | 总控、复位、清除、安装、退房钟点、校时、原始直写（危险区） |
| 5 | 房间 | 见"房号生命周期" |
| 6 | 发卡记录 | 分页/筛选/导出 CSV、详情含原始字节 |
| 7 | 设备与诊断 | 端口探测、驱动指纹、自检 27/27、导出诊断包 |
| 8 | 设置 | 串口、运行副本路径、卡密码、操作员、备份/恢复 |
| 9 | 首启向导 | ①校验随包 SDK（显示 manifest 哈希）②选串口 ③**导入初始房号** ④设起始卡号 ⑤设管理员口令 |

### 读卡页规范

**A. 卡片数据区（无论有无记录都完整展示）**：卡型、房号/序号（房号查不到则显示序号 + "未登记"）、天数/小时/退房钟点、卡号 `0xXXXX`、28 字节 HEX（等宽、可复制）、读卡器 ID、标记（月码段、低 4 位）。

**B. 记录区（差异化提示，不影响 A 区）**

- 命中：最近一条（时间、操作员、房号、卡型、时长、结果）+ "共 N 条"，可展开。
- 未命中：提示「未查到该卡的发卡记录（可能由原厂软件或其它机器发放）」+ "补录备注"入口；**A 区照常显示**。
- 空白卡：提示「空白卡 / 已退房，无卡号」，A 区显示原始字节。
- 查询异常：显示「记录查询失败（错误码）」，**不得显示成"未查到"**。

### 房号生命周期

```
初始：首启向导导入 ini/CSV
新增：填房号 → 系统分配序号 → 制作安装卡 → 到锁上刷一次 → 绑定完成
```

1. **序号分配**：`room_index` 取 0–255 中未使用的最小值，也可手填；唯一约束在库层强制。
2. **新增即生成安装卡**：房间保存后行内出现「制作安装卡」（admin），走 `--type install --room <房号>`，页2 固定 `46F20001`、不含卡号；二次确认后执行，写 `install_card_at` + 审计。
3. **锁只认序号**：安装卡不编码房号，房号是本系统的登记名。
4. **改房号**：只允许改显示名，序号不可改。
5. **停用**：`active=0`，不可发卡、不参与分配，序号保留。
6. **删除**：仅逻辑删除，不物理删行 → 唯一约束天然阻止复用。
7. **上限**：序号最多 256 个，用尽提示（v1 单楼栋）。

**权限**：`frontdesk` = 读卡/发客卡/查记录/导出；`admin` 追加管理卡、房号（含制作安装卡）、设置、操作员、备份、原始直写。

## 8. 安全与护栏

- 1095 天卡：需输确认词，写明"会把该房间有效卡顶到 3 年后"。
- 复位/清除/安装卡：admin + 二次确认 + 操作前自动备份 DB + 审计。
- 幂等：24h 幂等键，重复提交只发一张卡、一条记录。
- 鉴权：Argon2id，无默认口令，首启强制设置；会话在内存。
- 本地面：无 HTTP 服务、无远程内容、CSP 严格、capabilities 白名单。

## 14. 显式假设

1. 许可证 **AGPL-3.0**，SDK 与产品同许可。
2. SDK 与驱动**随安装包分发**（可开关回退）。
3. v1 不做：房态/入住/账务/报表、挂失与应急卡、多门店同步、自动更新、手机端、制卡打印机模板；打印仅 `window.print()`。
4. 单机、单读卡器；多操作员共用一台机器；**单楼栋、序号上限 256**。
5. 房号由本系统维护，不读原厂数据库；初始数据一次性导入，之后新增房号靠安装卡绑定门锁。
6. 发布二进制但不做代码签名，首次运行有 SmartScreen 提示。

**环境教训（已写入产品 README）**

- 仓库路径含中文 → MSVC 报 `D8050`；解法：`CARGO_TARGET_DIR` 指向 ASCII 路径 + `DEBUG=false`（去掉 `/Z7`）。
- 安全软件锁 `%TEMP%` → esbuild 删临时文件失败；解法：`TEMP` 指到工作区内。
- 本机原先没有 Rust / MSVC / Windows SDK，已装 Rust 1.99.1 与 VS Build Tools 2022（VCTools + Win11 SDK）。

**偏差记录**

- 打包需先跑一次 `npm run setup:nsis`：tauri-cli 自带下载器在本机必超时。根因是工具链必须解到  `%LOCALAPPDATA%\tauri\NSIS\` 的**直接一层**（`makensis.exe`/`NSIS.exe`/`Bin\` 在 `NSIS\` 下），
  摆成 `NSIS\nsis-3.13\` 会被判"缺文件"后删除重下。脚本已固化 13 项必需文件与两个 SHA1。
- `dev` 目前依赖系统安装的 .NET Framework 4.8 与 csc；未做 .NET 可用性预检（计划里排在 R3）。
- 管理卡六类 + 原始直写、二次确认、审计已实现；**角色鉴权未做**（目前仅靠二次确认兜底）。
- 备份/诊断、发卡记录页、首启向导仍未实现（M5）。

**实跑发现并修复（2026-11-05 首次启动演示）**

| 现象 | 根因 | 修复 |
|---|---|---|
| 发卡页房间下拉是空的，提示"请先选择房间" | `IssueCard` 的 useEffect 依赖 `[]`，组件在房间创建前就挂载过，之后不再拉列表 | App 里加 `roomsVersion` 计数，房间变更 +1，发卡页/管理卡页据此重拉 |
| 记录时间显示 `2026-11-05T09:57:27Z` | SQLite 存 UTC，前端直接渲染 | 统一 `formatTime()` 转本地时区 |
| `cargo build --release` 后窗口显示 `ERR_CONNECTION_REFUSED` | 缺 `custom-protocol` feature，编出来的是 dev 壳，去连 `localhost:5173` | `Cargo.toml` 补 feature；README 写明发布必须走 `tauri build` |
| **dev 模式下点「探测端口」报"设备输出无法解析：ports 没有输出"** | `PMSLockCard.exe` 是 .NET FW 程序，往管道写 **GBK**；设备层用 `read_to_string`（要求 UTF-8）解码失败后返回空串 | 改为读字节 + 先 UTF-8 再退回 GBK（`encoding_rs`）；加单测锁住 |

**真机样本带来的修正（2026-11-05）**

它只调用 SDK 的 `CardBuilder` / `CardNoStore`，做三件事：分配卡号（`Next()` 会落盘）、按房号序号+时长构包、
拼 28 字节输出 JSON。`SimDevice::issue_guest()` 调它，于是模拟发卡 = 真机的"构包 + 计数器"部分，
只少了串口写卡。

| 验证 | 结果 |

同时把"模拟设备样本固定"的过时提示改成"会用 SDK 离线构包并推进计数器，只是不真写卡"。

**第十六轮：写卡前统一先读卡（2026-11-05）**

| 项 | 处理 |
|---|---|
| 统一前置 | 新增 `pre_read_card()`：发客卡（含续住）、安装卡、管理卡在**写之前**都先读一次卡 |
| 失败提示 | 读不到卡直接中断，报"写卡前读卡失败：…（先把卡放到读卡器上，确认串口没被原门锁软件占用）"，不会等到设备层才报含糊错误 |
| 留痕 | 预读结果打终端：`[write] 写卡前预读：日租客卡 · 0x2404` |
| 退卡类 | 「持卡退房 / 读卡退房」本来就是读卡后动作，无需改动 |

实测（模拟模式）：右键 201 → 发行房卡 → 发卡。
日志出现 `[write] 写卡前预读：日租客卡 · 0x2404`，随后写卡结果为 `0x240E`，顶栏水位同步 `0x240E`。

注：模拟设备没有真实卡，预读返回的是内置样本（所以日志里显示 0x2404）；真机上预读会返回读卡器里那张卡的实际情况。
**第十七轮：换房（2026-11-06）**

| 项 | 处理 |
|---|---|
| 入口 | 房间右键菜单「换房」，无有效客卡时置灰并说明原因 |
| 预览 | `room_move_preview` 只读返回：有效卡张数、最晚到期、最近一张有效客卡的客人信息/卡型/时长 |
| 执行 | `room_move_out`：校验目标房存在、未删除、≠源房 → 源房全部有效客卡登记退房（房态转设置值）+ 审计 `move_room` |
| 续接 | 退房后直接打开目标房发卡表单，客人信息与剩余时长（按原卡型向上取整）自动带入 |
| 提示 | 旧卡仍能开源房门、需收回；目标房房态不自动变 |
| 读卡核对 | 换房前**必须先读卡**（未读卡确认按钮置灰）；卡号属于源房有效卡 → 绿色通过；不属于 → 警告 + 二次确认（列出源房有效卡号清单），确认后审计记 `readCard=0xXXXX` |

为什么必须重新写卡：房号只编码在卡内页1 的**序号**里，旧卡的序号指向旧房，退房登记不会改变锁内的卡记录。
