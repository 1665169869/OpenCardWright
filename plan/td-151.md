# TD-151 校时卡字段与原厂 demo 对齐验证

**优先级** P1 · **状态** 已完成 · **来源** US-1106-45 · **模块** 发卡与卡片

> **结论（2026-11-08，2026-11-10 更正）**：校时卡编码的是 `YYMMDDHHmm`（年月日时分），全部字段已解出并与 demo 双向验证。
> - `YYMM` 在页2[3]（高 4 位年、低 4 位月；`0xAB`→2611、`0xBB`→2711）
> - `DD` 在卡号日段；`HH:mm` 在页1[2..3] 位域：
>   `页1[2] = 16 × (分 & 0x0F) + 9`、`页1[3] = (分 >> 4) + ((4 × 时) & 0x7C)`
> - 页1[2] 必须 `& 0x09 == 0x09`，否则读卡返回错误 4
> - 页2[0] = **`0x06`**（明文，IDA: `LOBYTE(v14[2]) = 6`）；旧样本 `0x14` 是加扰残留
> - 页2[1..2] = 卡号（`DDHHII`）；卡号的序号段对校时卡不承载时间含义
> - 旧拟合 `值 = 16 × 当日分钟数 + 953` **已废弃**（只在 19:47 那组样本下近似成立）
> - 写卡流程是「整卡读入 → 只改需要改的字节 → 写回」，所以 demo 写的卡 `页2[3]` 保留原值

**为什么做**：我们现在的校时卡字节是「照抄 + 归纳」得来的（`值 = 16 × 当日分钟数 + 953`、
页2 首字节 `0x14`），**含义一直没解出来**。原厂 demo 有「读时钟 / 写时钟」两个按钮，
可以直接对照它的读回值与写卡参数，确认我们算的到底对不对。

**现状**【核实】：`CardBuilder.BuildTimeSync` 的公式来自实测样本；`RWCardDemo` 的
「读写时钟信息」区需要填「作业流水号 / 时钟 / 发卡序号」三项，与我们的现实现是否一一对应未验证。

**改动点**
1. 用原厂 demo 写一张校时卡，记录它填入的三项参数与卡内 8 字节；
2. 用我方 `PMSLockCard.exe` 按同一时刻写一张，逐字节比对；
3. 若不一致，反推 `953` 常数与 `0x14` 首字节的真实含义（可能是「分钟数偏移 + 校验位」）；
4. 结论写进 `docs/TEMIC门锁卡技术规格.md` §5.3 与 `抓包样本与验证记录.md`。
