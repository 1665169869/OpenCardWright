# TD-121 抽屉显示有效卡 + 无卡退房改选卡（只退选中的）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-21 · **模块** 房间与预订

**为什么做**：① 网格点房间的抽屉里看不到该房现在有哪几张有效卡；② 无卡退房原来是「按房一键全退」，前台想退其中一张时无从下手。用户要求抽屉下面显示有效卡、无卡退房先展示张数再让用户选卡（已拍板：**只退选中的，可多选**）。

**现状**【核实】：抽屉只有改房名/房态/房型/上限/安装卡，无卡片列表；`noCardCheckout` 直接 `api.checkoutRoom` 全退；store 有 `active_guest_card_nos` / `latest_active_guest_card` 但无「按房列完整有效卡」的命令。

**改动点（零后端改动）**
1. 抽屉：`openRoom` 时 `loadDrawerCards`（`list_issuances({roomNo})` 200 条，有效客卡口径过滤、按卡号取最新排序），`Drawer onClose` 清空；参数区后新增「有效客卡（N 张）」区块 —— 逐行 `卡号 · 卡型 · 时长 · 到期 · 客人`（复用 `formatCardNo`/`formatTime`），空态灰字「当前没有有效客卡」，注释注明张数以列表实查为准；纯展示无按钮。
2. 无卡退房：右键改为打开新组件 `NoCardCheckoutModal`（不再全退）——标题下「{房号} 当前有 N 张有效卡」，Table 多选（**默认不勾**，卡号/卡型/时长/到期/客人五列），「退选中的卡（N）」未勾禁用 +「取消」；确认循环 `api.checkoutCard`，全成功 notice `已退 N 张有效卡（0x2288…），剩余 M 张` 并 reload，部分失败列出原因并留在弹窗可继续；0 张空态禁用。
3. `api.checkoutRoom` / `checkout_room` 命令与封装保留（前端不再调用，批量全退能力仍在后端）。

**验收标准**
- [x] 抽屉下方显示该房有效卡列表（打开实查、关闭清空）与张数
- [x] 无卡退房弹窗默认不勾、可多选、只退选中的
- [x] 成功 notice 带卡号与剩余张数；部分失败列原因可继续
- [x] 0 张有效卡空态 + 按钮禁用
- [x] `pnpm exec tsc --noEmit`、`cargo test --workspace` 119 项、`git diff --check` 全过；后端零改动

**依赖 / 风险**：复用 `checkout_card`（含审计与 remaining）；`checkout_room` 命令保留不动；抽屉列表与 `room.activeCards` 同口径独立计算（以列表为准）。
