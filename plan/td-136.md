# TD-136 管理卡新增「空白卡」卡型

**优先级** P1 · **状态** 已完成 · **来源** US-1106-38 · **模块** 发卡与卡片

**为什么做**：旧卡回收、现场销毁废卡时，之前只能用「原始直写」手工填 `00000000/00000000`，
容易填错，而且记录里显示「原始直写」，事后看不出这是故意擦卡。

**拍板**：后端加独立卡型（不是复用 raw），让日志/CSV 显示「空白卡」。

**改动点**
1. `AdminCardRequest` 新增 `Blank` 变体：`label()` → 「空白卡」，`to_args()` 走 `--type raw --p1 00000000
   --p2 00000000`（与持卡退房的擦卡同字节，但经 `issue_admin_card` 通道、有独立记录与二次确认）。
2. 设备层 `CardKind::from_label` **原本就识别「空白卡」**（`parse.rs:43`）并配 `is_blank()`，读回时正确显示。
3. 前端 `AdminCards.tsx`：`Kind` 加 `blank`，下拉「空白卡（清零）」，后果说明「锁会当无效卡拒开」，
   确认按钮走 danger；`api.ts` 的 `AdminCardKind` 加 `{ kind: 'blank' }`。
4. 手册 §4 管理卡表加「空白卡」行；新增单测 `blank_card_writes_all_zero_bytes`。

**验收标准**
- [x] 卡型下拉出现「空白卡（清零）」并需二次确认
- [x] 参数为 `--type raw --p1 00000000 --p2 00000000`（单测断言）
- [x] 发卡记录/CSV 显示「空白卡」而不是「原始直写」
- [x] `cargo test --workspace` 全绿（命令层 47 项）；`pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：真机上写空白卡后，读卡页应显示「空白卡」（`is_blank()` 已就绪），未在真锁上验证过效果。
