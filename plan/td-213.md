# TD-213 房间排序改为房号优先、序号次之

**优先级** P2 · **状态** 已完成 · **来源** US-1109-6 · **模块** 房间与预订

**为什么做**：用户希望房间列表/日历等按房号阅读，而不是按门锁序号排列；房号相同再按序号。

## 现状

- `ocw-store::list_rooms` 当前是 `ORDER BY r.room_index`（`app/src-tauri/crates/ocw-store/src/lib.rs:511`）。
- 前端 `RoomManager` / `RoomCalendar` 等直接消费 `listRooms` 返回顺序，没有二次排序。
- 因此现场看到的房间顺序是「序号优先」，与用户要求相反。

## 改动点

- 将 `list_rooms` 排序改为：
  - 主排序：`room_no`；
  - 次排序：`room_index`。
- 所有消费 `listRooms` 的房间列表、房态日历行、房间选择器自动跟随，无需各自排序。
- 明确 `room_no` 的比较方式：
  - 若房号都是纯数字，按自然数值排序（`201 < 202 < 1001`）；
  - 若存在字母/混合房号，再按字符串兜底；
  - 不要只做 SQLite 默认字符串排序，否则 `1001` 会排在 `201` 前面。
- 补测试：构造房号与序号相反的记录（如 `room_no=1001, room_index=1`、`room_no=201, room_index=9`），
  断言返回顺序是 `201` 在前、`1001` 在后；同房号时按序号。

## 验收标准

- [ ] 房间列表按房号优先展示；房号相同再按序号。
- [ ] 房态日历行、房间选择器、批量操作列表使用同一顺序。
- [ ] 纯数字房号按自然数值排序，不出现 `1001` 排在 `201` 前。
- [ ] 新增/复活/删除房间后顺序仍然稳定。
- [ ] `cargo test --workspace` 通过。
