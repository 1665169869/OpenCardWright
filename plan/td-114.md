# TD-114 日历房态 tag：房号旁房态 + 入住/预定状态

**优先级** P2 · **状态** 已完成 · **来源** US-1106-14 · **模块** 房间与预订

**为什么做**：用户刚给 219 发了卡，日历上却看不出这间房有没有人住。要求：还在预定状态标「预定」tag，办理了入住显示「入住」tag，房号左边同时显示房间当前的房态。

**现状**【核实】：`RoomCalendar.tsx` 房号列只有「色点 + 房号」，色点只对 `reserved` 特判；无任何状态信息。数据其实都已就位：`rooms` 自带 `activeCards`（发卡 reload 后立即 +1），日历已拉当月预定 `list`。

**改动点**
1. `RoomCalendar` 加 `statuses: RoomStatus[]` prop，`RoomManager` 调用处传 `statuses={statuses}`（与房间格子同一份数据）。
2. 房号列改两行布局（`flexDirection: column`，`ROOM_COL_W 100→132`）：第一行 = 色点 + 房号 + **房态 tag**（label/颜色来自 statuses，色点背景也改用 `st?.color`）；第二行 = 状态位。
3. 状态位优先级：`room.activeCards > 0` → 绿色**「入住」**；否则 `bookedToday(room)` → 蓝色**「预定」**；都没有 → 空（房态 tag 仍在第一行）。
4. `bookedToday` 用日历已拉的 `list` 判定（`checkIn <= today < checkOut` 且 `booked`），零新增查询。
5. 补 RoomCalendar 的 antd `Tag` import。

**验收标准**
- [x] 发卡后 `activeCards > 0`，日历刷新即显示「入住」tag
- [x] 无有效客卡但当天有预定的房间显示「预定」tag
- [x] 房号旁显示当前房态（label/颜色与房间格子一致）
- [x] 两个条件都不满足时只显示房态
- [x] 零新增查询；`pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：以 `activeCards > 0` 为入住判据（发卡即入住，与「有效卡」口径一致）；不引入独立的入住事件。
