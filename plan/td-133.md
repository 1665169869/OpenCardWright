# TD-133 备份列表漏列导入/自动备份（导入后看不到「恢复」按钮）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-35 · **模块** 记录与运维

**为什么做**：用户导入外部备份后，列表里找不到那一行，也就没有「恢复」可点。

**根因**【核实】：`list_backups` 的过滤只放行 `is_safety`（`.before-restore-*` / `.bak`）与
`name.starts_with("ocw-")`；而三种备份的命名并不统一——
手动备份 `ocw-{stamp}.db` ✅、**自动备份 `auto-{stamp}.db` ❌**、
**导入 `imported-{stamp}-{原名}` ❌**。后两种落盘成功却被 `continue` 跳过，
所以「自动备份」也一直不在列表里（同源缺陷）。前端每行是无条件渲染「恢复」按钮，
问题完全在后端过滤。

**改动点**
1. 抽出 `is_backup_name(name)`：认 `ocw-` / `auto-` / `imported-` 前缀，以及
   `.before-restore-*` / `.bak` 安全副本。
2. `list_backups` 的过滤改用它（安全副本分目录的逻辑不变）。
3. 新增单测 `backup_name_filter_covers_all_sources`：四种来源都放行，
   正在用的 `opencardwright.db`、`-wal`、无关文件都被拒。

**验收标准**
- [x] 导入的 `imported-*` 出现在备份列表里，可点「恢复」
- [x] 自动备份 `auto-*` 出现在列表里（打「自动」标签）
- [x] 正在用的库与 WAL 仍不冒充备份
- [x] `cargo test --workspace` 全绿（125 项，含新用例）

**依赖 / 风险**：纯后端过滤修正，前端无需改；**要重新打包安装才生效**（现装的 release 版仍是旧逻辑）。
