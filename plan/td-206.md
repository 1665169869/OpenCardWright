# TD-206 客人姓名查询支持 jieba 分词

**优先级** P2 · **状态** 已完成 · **来源** US-1109-3 · **模块** 记录与运维

**为什么做**：当前客人姓名是整串 `LIKE '%输入%'` 模糊匹配；输入「张三 丰」或「欧阳 娜娜」这类带空格/分词的姓名时，匹配不到或结果不稳定。希望用 jieba 分词后按词组合查询。

**现状**
- `app/src/pages/Logs.tsx:557-566`：预定记录页的「客人姓名（模糊）」输入框直接把整串传给后端。
- `app/src-tauri/crates/ocw-store/src/lib.rs:1011-1012`：`search_reservations` 使用单条 `r.guest_name LIKE '%' || ? || '%'`。
- 入住/发卡记录若也有姓名过滤，沿用同一套分词策略，避免两个页面的匹配口径不一致。

**改动点**
1. 在查询层接入 jieba：把输入切成词，过滤空白/单字噪声，生成 `(guest_name LIKE %词1% OR guest_name LIKE %词2% ...)`，再与房号/状态/日期条件 AND。
2. 分词结果为空或全部被过滤时，回退原文整串 `LIKE`，不能因为分词失败把查询变成“全表”。
3. 所有词仍走参数绑定，不拼 SQL；限制最多 N 个词，避免超长输入。
4. 补单元测试：单姓名、带空格姓名、英文/数字、空输入、无匹配。

**验收标准**
- [ ] 输入「张三」「张三 丰」都能命中「张三丰」
- [ ] 多词查询不会返回与任一词都无关的记录
- [ ] 空输入仍返回全部；分词失败回退原文模糊匹配
- [ ] 预定记录与入住/发卡记录（如有姓名过滤）行为一致

**待拍板**：分词放后端还是前端？建议后端 `jieba-rs`（查询逻辑集中、可复用、可单测）；这会新增 Rust 依赖，需要确认可接受。
