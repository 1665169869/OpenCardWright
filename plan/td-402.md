# TD-402 数据库备份 / 恢复

**优先级** P0 · **状态** 已完成 · **来源** RM5 · **模块** 记录与运维

**为什么做**：发卡记录、房间、操作员全在一个 SQLite 文件里，丢了等于全部重来，而现在没有任何备份或恢复手段。

**现状**【核实】：无实现。库在 `%PROGRAMDATA%\OpenCardWright\opencardwright.db`，WAL 模式。

**改动点**
1. `ocw-store`：加 `backup_to(path)`，优先 `VACUUM INTO`（无需新依赖）。
2. `commands.rs`：`backup_database` / `restore_database`（管理员 + 审计）。
3. 恢复前先 `PRAGMA wal_checkpoint(TRUNCATE)`，并把当前库另存为 `*.before-restore.bak`。
4. 恢复后提示「需要重启应用」，或直接重启。

**验收标准**
- [x] 备份文件能在另一台机器用只读连接打开，表数量与 `schema_version` 一致（`inspect_backup` 单测覆盖）
- [x] 恢复后房间 / 发卡 / 操作员 / 房型都在（`backup_and_restore_roundtrip`）
- [x] 恢复前自动留 `.before-restore-*.bak`，`.gitignore` 已覆盖 `*.bak` / `*.before-*.bak`
- [x] 操作写入审计（`backup_database` / `restore_database`）

**依赖 / 风险**：WAL 不 checkpoint 会丢最近事务 —— 已在 `restore_database` 里先 `wal_checkpoint(TRUNCATE)`
并在注释写明；备份不包含 `CardNo.state`（运行目录），换机要单独拷，界面上已提示。
