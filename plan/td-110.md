# TD-110 相邻预定半格错位 + 色块颜色随机

**优先级** P2 · **状态** 已完成 · **来源** US-1106-10 · **模块** 房间与预订

**为什么做**：张三 6→7、李四 7→8 同房相邻时，两条色块在 7 号列叠放，看起来房间被占了两三天；且所有预定同一青色，难以分辨是哪一条。用户拍板：**半格错位显示**（数据层不改）+ 色块颜色随机。

**现状**【核实】：`RoomCalendar.tsx` 的 `spanOf` 终点在退房日+1 的格缘、起点无衔接判断，相邻两条在退房日列完全重叠；`background` 写死 `#13c2c2`。

**改动点**
1. `spanOf` 改连续坐标（单位=格，可带 0.5）：终点 = 退房日格**中点**；起点 = 入住格左缘，同房存在「前序退房日 = 本条入住日」时 +0.5（衔接半格）；与视窗 `[from, to)` 相交才画，跨月终点取月末右缘。
2. 色块 `left = s*COL_W+2 / width = (e-s)*COL_W-4` 对小数坐标天然成立，渲染公式不动。
3. 新增 `BLOCK_COLORS` 调色板（8 色）与 `blockColor(id)`：按预定 id 稳定取色（同一条每次同色），过期仍统一灰。

**验收标准**
- [x] 张三 6→7 画到 7 号格中点；李四 7→8 从 7 号格中点起画 —— 7 号列左半张三、右半李四
- [x] 不同预定颜色不同且稳定（按 id 取模，非每次渲染随机）
- [x] 跨月预定在两个月视图各画正确半段（跨月终点取右缘、起点不重复加半格）
- [x] 数据层重叠校验未动，6→7 与 7→8 仍可创建
- [x] `pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：纯前端渲染；同日三段以上衔接（A 退 B 入、B 退 C 入同一天）同样按半格递推成立。数据层不改 —— 同日退+入是否允许属业务语义，若日后要禁另立条目。
