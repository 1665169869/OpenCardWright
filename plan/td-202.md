# TD-202 预定房间改为选择日期 + 主入口移出右键菜单

**优先级** P1 · **状态** 已完成· **来源** US-1106-3 · **模块** 房间与预订

**为什么做**：现有预定只把房态改成「预定房」，不记日期，前台无法回答「这间房被订到几号」；入口还藏在右键菜单里，新前台找不到。用户已确认：预定必须能选入住—退房日期，且入口放在房间卡片上，不做二级菜单。

**现状**【核实】：
- `app/src/pages/RoomManager.tsx:445` `handleReserve` 只调 `api.setRoomStatus(roomNo, 'reserved')`，注释写明「不记预定时间、不写卡」；右键菜单在 `:619` `roomMenu()`，`:642` 是「预定房间」项。
- `ocw-store/src/schema.sql:14` 的 `room` 表只有 `status`，没有预定日期字段；`schema_version` 当前为 7（`ocw-store/src/lib.rs:372`）。
- `commands.rs:1433` `set_room_status` 只改房态并记审计；前端 `RoomManager.tsx:59` 的注释与 `ISSUABLE_STATUS` 白名单使预定房不能发卡。
- TD-201 当时按 Q-201 选了「只改房态、不记时间」，带日期方案留到 TD-202；本次用户明确要改。

**改动点**
1. `ocw-store`：新增 `reservation` 表（`id`、`room_no`、`check_in`、`check_out`、`guest_name?`、`status`、`created_at`、`created_by`、`cancelled_at?`），迁移到 schema v8；提供 `insert_reservation` / `update_reservation` / `cancel_reservation` / `list_reservations(from, to)` / `reservation_overlaps(room_no, check_in, check_out, exclude_id?)`。日期统一 `YYYY-MM-DD`；**退房日不含**（11-06 → 11-07 表示住 1 晚），在代码注释与验收里写死。
2. `commands.rs`：新增 `create_reservation` / `update_reservation` / `cancel_reservation` / `list_reservations`；写操作按登录角色收口并写审计。日期非法、退房 ≤ 入住、同房区间重叠返回 4xx。创建成功把 `room.status` 置 `reserved`；取消时默认改回 `vacant_clean`（可逆默认，见风险）。
3. 前端 `RoomManager.tsx`：房间卡片右上角加显式「预定」按钮（主视图，非右键菜单），点击开受控 Modal；Modal 用 `DatePicker` 选入住/退房（默认今天/明天），显示「住 N 晚」；已有预定可点开改期/取消。
4. 右键菜单移除「预定房间」项（可保留「查看预定」作为辅助，但不能是唯一入口）；删除旧 `handleReserve` 路径。
5. 审计：创建/改期/取消都写 `audit_log`，详情带房号与日期区间。

**验收标准**
- [x] 房间卡片上可见「预定」按钮，点击能选入住/退房日期；右键菜单不再是预定入口
- [x] 退房 ≤ 入住、过去日期、同房区间重叠都被拒绝，库中无半条记录
- [x] 创建成功后 `room.status='reserved'` 且 `reservation` 有记录；取消后记录保留（`cancelled_at`）且房态按约定回退
- [x] 同一房间多段不重叠预定可共存；跨月/跨年区间正确
- [x] `cargo test --workspace` 有存储层与命令层用例（重叠、非法日期、取消、审计）；`pnpm exec tsc --noEmit` 通过
- [x] 原有「有有效卡不许改名/删房」「删房逻辑删除」等铁律未被破坏

**依赖 / 风险**：`schema_version` 从 7 升 8，必须可重复迁移且旧库无损。预定房不能发卡沿用现有白名单；若要允许「预定 + 发卡」超售，另立条目。**到期不自动改房态**（用户已定），过期预定在日历上显示为历史。取消后房态默认空净是可逆默认值，若与现场流程冲突再改。
