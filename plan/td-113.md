# TD-113 当天预定发卡前确认「是否给这位预定客人发卡」

**优先级** P1 · **状态** 已完成 · **来源** US-1106-13 · **模块** 发卡与卡片

**为什么做**：TD-107 会把当天预定姓名**自动预填**进发卡表单，但没问一句「确定是这位客人吗」——走错房、客人换人时会静默写错姓名。用户要求：预定到当天了，发卡时弹确认。

**现状**【核实】：`RoomManager.tsx` 的 `openIssue`（TD-107）拉到覆盖今天的预定后直接 `setIssueGuest` + `setIssueRoom` 打开表单，无确认环节。

**改动点**
1. 新增 `issueConfirm: { room, mode, res } | null` state。
2. `openIssue` 改造：命中 `status='booked'` 的当天预定 → `setIssueConfirm` 弹确认并 `return`；无预定或拉取失败 → 直接 `setIssueRoom` 打开（原行为）。
3. 新增 `confirmIssue(useGuest)`：true 且有姓名 → `setIssueGuest({ name: res.guestName })` 后打开；false → 清空姓名打开；统一 `setIssueMode` + `setIssueRoom`。
4. 受控确认 Modal：房号标题、`checkIn → checkOut` Tag、姓名、备注；三按钮 —— **「是，按预定客人发卡」**（primary，无姓名时禁用）、「不是，手动填写」、「取消」（只清状态不开表单）。

**验收标准**
- [x] 该房覆盖今天有预定时右键发卡先弹确认，不直接进表单
- [x] 「是」预填预定姓名打开；「不是」不预填打开；「取消」不打开
- [x] 预定没填姓名时「是」按钮禁用，只能手动填写
- [x] 无预定 / 拉取失败直接打开发卡表单（不被确认框挡住）
- [x] `pnpm exec tsc --noEmit` 与 `cargo test --workspace` 通过

**依赖 / 风险**：只动前端入口；确认框只在 `openIssue`（右键发卡 / 续卡）路径，换房 move 不受影响。
