# TD-229 发卡记录有效期检测（后端状态字段）

**优先级** P1 · **状态** 已完成 · **来源** US-1111-6 · **模块** 记录与运维

**为什么做**：发卡记录里已经过期的**总控卡**、以及部分**客卡**仍显示「有效」。
用户要求：总控卡与客卡都要做有效期检测，过期后不能显示有效。

## 现状与根因【核实】

- 状态列在 `app/src/pages/Logs.tsx:248-261`：
  ```tsx
  const guest = r.kind === '日租客卡' || r.kind === '钟点客卡'
  const expires = r.expiresAt ? Date.parse(r.expiresAt) : NaN
  if (guest && Number.isFinite(expires) && expires <= Date.now()) {
    return <Tag color="red">已过期</Tag>
  }
  return <Tag color="green">有效</Tag>
  ```
  **过期判断被 `guest &&` 限定在客卡**，总控卡永远落到「有效」。
  注意：**只有客卡（日租 / 钟点）与总控卡有到期时间**（用户 2026-11-11 确认）；
  复位 / 清除 / 安装 / 退房钟点 / 校时卡的 `days`、`hours` 都是 0 → `expires_at` 为 NULL，
  本来就不参与过期判断。
- `IssuanceRow`（`ocw-store`）只有 `expires_at` / `checked_out_at`，没有统一状态；前端各自 `Date.parse` 比较本地时间。
- 安装卡 `days/hours = 0`（`commands.rs:470-482`）→ `expires_at` 为 NULL，本来就不会过期。
- **客卡也显示有效**的另一个可能：旧数据 `expires_at` 为 NULL（v7 回填前的记录），需在实现时确认
  （记录页按「到期」列为空即可筛出来看）。
- 管理卡到期写入：`issue_admin_card`（`commands.rs:763-778`）用 `card.days/hours` 落库，
  `record_issuance` 对 `days > 0 || hours > 0` 的记录写 `expires_at`（`expiry_modifier`），所以总控卡有到期时间。

## 改动点

1. **后端**：`IssuanceRow` 新增 `status: String`；`list_issuances` 的 SQL 用 `CASE WHEN` 计算：
   - `result != 'ok'` → `failed`
   - `checked_out_at` 非空 → `checked_out`
   - `invalidated_at` 非空 → `voided`
   - `expires_at` 非空且 `<= now` → `expired`
   - 其余 → `active`
   与日历 `list_guest_stays` 的 status 命名保持一致。
2. **前端** `Logs.tsx` 状态列改为映射：`failed` → 失败（红）、`checked_out` → 已退房（默认）、
   `voided` → 已作废（紫）、`expired` → 已过期（红）、`active` → 有效（绿）；
   删除前端的 `Date.parse` 与 `guest` 限定。
3. **无到期卡型**：`expires_at` 为 NULL 且 `status = active` 的——安装卡、复位卡、清除卡、退房钟点卡、
   校时卡——显示「有效（无期限）」或「—」，与「有到期但未过期」区分开；
   这些卡型**不做**过期判断。
4. **导出**：CSV 已有「到期时间」列；可选加一列「状态」保持一致（实现时一并定）。

## 验收标准

- [ ] 总控卡过期后在发卡记录显示「已过期」（不再显示有效）
- [ ] 客卡过期后同样显示「已过期」
- [ ] 复位 / 清除 / 安装 / 退房钟点 / 校时卡（无到期）不做过期判断，显示「有效（无期限）」或「—」
- [ ] 已退房 / 已作废 / 失败分别显示对应 tag，不再混成「有效」
- [ ] `ocw-store` 增加一条 SQL 状态用例（active / expired / checked_out / voided / failed）
