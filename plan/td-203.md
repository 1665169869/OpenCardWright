# TD-203 房态房间日历图（房间 × 日期矩阵）

**优先级** P1 · **状态** 已完成· **来源** US-1106-4 · **模块** 房间与预订

**为什么做**：现在房间页只显示「此刻」的房态，前台无法看到未来哪些天被预定、哪些房间空着。用户明确这是本轮最重要的需求：要在一张日历上看到不同房间被预定的日期。

**现状**【核实】：
- `app/src/pages/RoomManager.tsx` 只有格子视图：每个房间一张卡，按 `room.status` 着色；没有日期维度。
- 预定数据尚无日期字段/表（见 TD-202）；没有跨房间的日期查询命令。
- 房态 key `reserved` 已存在（`schema.sql:118`），但只表示「当前是预定房」，不表示日期区间。

**改动点（已与用户确认）**
> 形态：房间 × 日期矩阵；交互：空白格直接预定、点已有预定可改期/取消；语义：入住—退房日期区间，区间内显示预定，到期不自动改房态；入口：房间卡片「预定」按钮 + 日历空白格。

1. 房间页顶部加视图切换「房间 / 日历」（`Segmented`），日历为**行=房间、列=日期**的矩阵；默认当月，支持上一月 / 下一月 / 回到今天。
2. 列宽固定（约 36–44px），左侧房号列 sticky；横向滚动；周末 / 今天列有底色；房间按楼层 / 房号排序，支持房型筛选（可选）。
3. 预定用连续色块跨格显示（入住日到退房日前一天），格内显示客人名 / 短标记；当前房态作为行首或格子底色，避免与预定混淆。
4. 空白格点击 → 打开 TD-202 的预定 Modal，预填该房 + 该日期；已有预定色块点击 → 详情（客人、日期、创建人），可改期 / 取消；复用 TD-202 命令。
5. 数据一次性拉取 `list_reservations(month_start, month_end)`（含跨月区间），前端按房间分组渲染；不要每格发请求。
6. 空库 / 无预定时给空状态；过期预定显示为灰色历史，不自动改房态。

**验收标准**
- [x] 日历视图能一眼看到 30 间房 × 当月每天哪些被预定；跨月预定在两个月都可见
- [x] 空白格点击预填房号与日期；已有预定点击可改期 / 取消，操作后日历即时刷新
- [x] 退房日不显示为预定（与 TD-202 的区间口径一致）；连续预定不重叠
- [x] 切月、今天按钮、横向滚动正常；左侧房号列不随横向滚动丢失
- [x] 30 间房 × 31 天无 N+1 查询（一次 `list_reservations`），页面无明显卡顿
- [x] 日历与房间页房态一致；预定房仍不能发卡（沿用现有白名单）
