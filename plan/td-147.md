# TD-147 卡号不带时间戳 → 读卡器解出假日期

**优先级** P1 · **状态** 已完成 · **来源** US-1106-43 · **模块** 发卡与卡片

> **解决（2026-11-08）**：卡号已改为时间戳编码（日5+时5+序号6），见 **TD-150**。
> 读卡器现在能解出真实发卡时间，`AB`（页2[3]）确认是**年+月**而非日期字段。

**为什么做**：实测发现这个字节**不是固定常量**，而是「年份 + 月日」字段。我们 `CardBuilder` 一直写死 `AB`，
等于每张卡都携带同一组年月日。

**现状**【实测，见 `docs/抓包样本与验证记录.md` §12.2】
- 基线 `5BEC3000 844922AB` → RWCardDemo 显示起始 `2026-11-04 09:00`
- `AB`→`0B`（清 bit7、bit5）→ **年份 2026→2016**（bit7 = 年 +8、bit5 = 年 +2）
- `AB`→`A0`（清低 4 位）→ 月/日变 `00` → RWCardDemo 报 `Run-time error '13'`
- 页2[3] 当前恒为 `AB` = `1010 1011`

**改动方向**
1. 先确定 `AB` 对应的「年/月/日」精确映射（还需 2～3 组样本：改 bit6/bit4/bit3/bit2/bit1/bit0 各一次）；
2. 评估按**发卡时间**生成该字节（`CardBuilder` 增加时间参数）；
3. 注意会影响 `selftest` 的 27 条黄金向量（现有向量页2 第 4 字节都是 `AB`，需一并复核）。

**验收标准**
- [ ] 位映射表补全（每个 bit 对应年/月/日的哪一位）
- [ ] 结论明确：锁是否校验该字段（若锁不校验，可保持 `AB` 只在文档里说明）

**依赖 / 风险**：改 `CardBuilder` 需要动 `sdk/`（只读约束）+ 重跑 27 条向量；若锁不校验，改了反而增加风险。
**待拍板**：**是否要改成按发卡时间生成**。建议默认：**先补全映射再决定**，在此期间保持 `AB`（实测能开门）。
