# TD-101 管理卡模拟构包按卡型区分

**优先级** P1 · **状态** 已完成 · **来源** ST-1, CL-0036-3 · **模块** 发卡与卡片

**为什么做**：模拟模式（`OCW_SIM=1`）下总控、复位、清除、校时卡回放的字节完全一样，演示时看起来「发什么卡都一样」，也没法用它验证读取侧的卡型分支。

**现状**【核实】：`app/src-tauri/src/state.rs:51` 的模拟分支只判断
`if args.contains(&"install")` → `INSTALL_JSON`，其余一律回放 `GUEST_DAY_JSON`；
`crates/ocw-device/src/sim.rs` 只有 `INSTALL_JSON` / `GUEST_DAY_JSON` 两个常量；
`tools/CardBuild.cs` 只支持客卡与安装卡。

**改动点**
1. `app/tools/CardBuild.cs`：加 `--type`（客卡 / 安装 / 总控 / 复位 / 清除 / 退房钟点 / 校时），调用 `CardBuilder` 对应分支。
2. `crates/ocw-device/src/sim.rs`：加 `AdminSpec` + `issue_admin()`，保留「缺构包器时退回固定样本」的兜底。
3. `src-tauri/src/state.rs`：删掉 install / 其余的二元回放，改为委托 `issue_admin()`；拿不到类型就报错，不要静默回放客卡。
4. `crates/ocw-device/tests/sim_cardbuild.rs`：补断言。

**验收标准**
- [x] 模拟模式下依次发六类管理卡，`raw_hex` 两两不同（`admin_cards_are_pairwise_different`）
- [x] 每类字节与 `PMSLockCard.exe selftest` 中同名向量一致（以 `docs/抓包样本与验证记录.md` 为准）
- [x] `cargo test -p ocw-device --test sim_cardbuild` 通过，新增 3 条（含安装卡不推进计数器）
- [x] 未改 `sdk/`（`git status sdk/` 干净）

**依赖 / 风险**：`CardBuild.cs` 在 `app/tools/`，可改；`sdk/*.cs` **不可改**（AGENTS §0/§9）。
