# TD-112 日历禁止修改昨天往前的数据

**优先级** P2 · **状态** 已完成 · **来源** US-1106-12 · **模块** 房间与预订

**为什么做**：用户要求日历上禁止修改昨天往前的数据 —— 过去日期不该能新建预定，已结束的预定不该再被改期 / 取消（误点会把历史记录改乱）。

**现状**【核实】：`RoomCalendar.tsx` 空白格 `onClick={() => onReserve(room, ds)}` 无日期限制；色块一律可点开 `onEdit`。数据层 create 已拒「入住日早于今天」，但 UI 层没有拦截。

**改动点**
1. 空白格：`ds < today` 时 `onClick` 置 `undefined`、`cursor: not-allowed`、`opacity: 0.45`、title 改「已过去，不可预定」。
2. 色块：`r.checkOut < today`（退房日在昨天或更早 = 已结束）禁点改期 / 取消，title 标「已结束，不可修改」；**今天退房的仍可调整**（客人上午才走）。

**验收标准**
- [x] 昨天及更早的空白格不可点，有视觉降透明与 not-allowed 光标
- [x] 退房日早于今天的预定色块不可点开编辑
- [x] 今天及未来的格子、今天退房的预定不受影响
- [x] `pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：纯前端拦截；后端 create/update 的日期校验仍在（双保险）。
**待拍板**：无
