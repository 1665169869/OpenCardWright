# TD-115 发卡成功后同步房态：空净/预定 → 未满（到顶 → 已满）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-15 · **模块** 发卡与卡片

**为什么做**：用户报 BUG —— 空净房发完卡房态还是「空净房」，前台看不出这间房已经有人住；日历上的房态 tag 也跟着错。

**现状**【核实】：`commands.rs` 的 `issue_guest` 落库后直接返回 `IssuedDto`，全程不调 `set_room_status`；房态只在退房 / 手工改时变化。发卡是房态变化的自然触发点，但后端没做同步。

**改动点**
1. `issue_guest` 落库块内、返回前加同步：`room.status ∈ {vacant_clean, reserved}` 时 `count_active_cards`，设了上限且已到顶 → `occupied_full`，否则 → `occupied_partial`。
2. 只在成功分支执行 —— 写卡失败保持原房态；维修 / 其他 / 已满房不覆盖。

**验收标准**
- [x] 空净房发卡成功后房态变为未满房（预定房发卡同样转未满）
- [x] 设了最大发卡数且有效卡到顶时变为已满房
- [x] 写卡失败不改房态（逻辑在成功分支内）
- [x] `cargo test --workspace` 118 项全绿；`pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：房态仍是可手工覆盖的业务字段，本改动只在发卡时顺手同步；退房链路的房态逻辑不变。
