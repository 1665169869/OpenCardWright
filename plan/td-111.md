# TD-111 过期宽限 1 天收紧到 10 分钟（到期提醒关不掉）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-11 · **模块** 提醒与通知

**为什么做**：用户反馈「到期提醒关不掉，哪怕房间已经没有有效卡了」。房间的「有效卡」口径是 `expires_at > now`，但自然过期的客卡没人退房（`checked_out_at` 为 NULL），旧窗口 `[now - 1 天, +N 分钟]` 让它在过期后 24 小时内一直被 `expiring_cards` 返回 —— 铃铛挂着、声音反复响，体感就是关不掉。

**现状**【核实】：
- `ocw-store/src/lib.rs` `expiring_cards` 窗口下界是 `strftime(..., 'now', '-1 day')`；`alerted` Set 只防重复弹通知，不影响铃铛 Badge（显示 `list.length`）。
- 开关链路本身是通的：`ReminderPanel.save → onChanged → App.getReminderSettings → setReminder → 轮询 effect` 重跑，`enabled=false` 即 `setReminders([])` 并停轮询 —— 用户遇到的「关不掉」是条目消不掉，不是开关失效。

**改动点**
1. `expiring_cards` 窗口下界 `'-1 day'` → `'-10 minutes'`：过期瞬间没赶上轮询的仍可补提醒，过期 10 分钟后必须出窗。
2. 同步函数注释与 `checkout_room` 处的窗口描述。
3. 测试：`expiring_cards_window_and_dedupe` 新增 `insert("-30 minutes","307")` 断言不出窗（TD-111 回归），原「-30 分钟要提醒」的 fixture 改为 `-5 minutes`（落在宽限内）。

**验收标准**
- [x] 过期超过 10 分钟的客卡不出现在 `expiring_cards`（307 回归用例）
- [x] 宽限内（过期 ≤10 分钟）与即将到期的卡仍正常提醒
- [x] 已退房的卡仍被排除（`expiring_cards_excludes_checked_out` 通过）
- [x] `cargo test --workspace` 118 项全绿；`pnpm exec tsc --noEmit` 通过
- [x] 设置里的开关链路复核无问题（此前已通，本次不改）

**依赖 / 风险**：只收紧查询窗口，不改写入；若现场需要更长的过期宽限（如跨班次补提醒），把 `-10 minutes` 调回合理值即可，建议不超过 1 小时。
**待拍板**：无（10 分钟宽限覆盖 30 秒轮询 + 20 秒通知时长，留了余量）
