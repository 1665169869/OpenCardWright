# TD-209 新增预定禁止早于今天入住

**优先级** P1 · **状态** 待办 · **来源** US-1109-3 · **模块** 房间与预订

**为什么做**：新建预定不应把入住日选到昨天或更早；当前前端只在部分入口做了限制，后端没有统一兜底，容易出现历史日期的新预定。

**现状**
- `app/src/components/ReservationModal.tsx:129`：新建时 `disabledDate` 禁止过去日期，但这是前端单点限制。
- `app/src/components/RoomCalendar.tsx:488`：日历空白格过去日期已标记不可预定（TD-112），但顶部「新增预定」和房间卡片入口是另外的路径。
- 后端新建预定的日期校验目前主要检查格式与 `checkOut > checkIn`，未明确拒绝 `check_in < 今天`。

**改动点**
1. 新建预定统一校验 `checkIn >= 本地今天`；三个入口（日历空白格、房间卡片、顶部新增按钮）都走同一校验。
2. 后端 `create_reservation` 增加同样的服务端校验，返回可读错误；不能只依赖前端。
3. 改期/编辑保留历史记录例外：已有预定的原入住日可以早于今天，但新的入住日不得早于今天（按产品确认）。
4. 补一条后端测试，覆盖昨天/今天/明天三个边界。

**验收标准**
- [ ] 新建预定不能选昨天或更早，前后端都拒绝
- [ ] 今天入住可以正常保存
- [ ] 改期历史预定不会被强制改成未来（仅限制新入住日）
- [ ] 错误提示明确指出「入住日不能早于今天」

**待拍板**：改期时是否允许保留原历史入住日？建议允许保留原值；若要改成新日期，新日期必须 >= 今天。
