# TD-209 新增预定禁止早于今天入住

**优先级** P1 · **状态** 已完成 · **来源** US-1109-3 · **模块** 房间与预订

**为什么做**：新建预定不应把入住日选到昨天或更早；当前前端只在部分入口做了限制，后端没有统一兜底，容易出现历史日期的新预定。

**现状**
- `app/src/components/ReservationModal.tsx:129`：新建时 `disabledDate` 禁止过去日期，但这是前端单点限制。
- `app/src/components/RoomCalendar.tsx:488`：日历空白格过去日期已标记不可预定（TD-112），但顶部「新增预定」和房间卡片入口是另外的路径。
- 后端新建预定的日期校验目前主要检查格式与 `checkOut > checkIn`，未明确拒绝 `check_in < 今天`。

**改动点**
1. 新建预定统一校验 `checkIn >= 本地今天`；三个入口（日历空白格、房间卡片、顶部新增按钮）都走同一校验。
2. 后端 `create_reservation` 增加同样的服务端校验，返回可读错误；不能只依赖前端。
3. 改期/编辑保留历史记录例外：已有预定的原入住日可以早于今天，但新的入住日不得早于今天（按产品确认）。
4. 补一条后端测试，覆盖昨天/今天/明天三个边界。

**验收标准**
- [x] 新建预定不能选昨天或更早，前后端都拒绝
      —— 后端 `validate_reservation`（`app/src-tauri/crates/ocw-store/src/lib.rs:919-980`，`check_in < today` → 955 行报错）；
      前端 `ReservationModal.tsx:139` `dateRangeOk = isEdit || !checkIn || checkIn >= localDay(0)` + 确认按钮 disabled。
      所有入口共用同一个弹窗（只有 `RoomManager.tsx:1399` 一处实例），不存在第二套校验。
- [x] 今天入住可以正常保存 —— 单测 `reservation_overlap_room_status_and_cancel` 用 `today→tomorrow` 建预定成功。
- [x] 改期历史预定不会被强制改成未来（仅限制新入住日）—— `create_reservation` 传 `allow_past_check_in=false`（1190），
      `update_reservation` 传 `true`（1224）。
- [x] 错误提示明确指出「入住日不能早于今天」—— 后端文案是「入住日期不能早于今天」；前端是提前拦截（按钮置灰），
      不会走到报错路径，因此没有额外提示文案。
