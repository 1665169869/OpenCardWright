# TD-107 预定房可发卡 + 预定姓名自动填入发卡界面

**优先级** P1 · **状态** 已完成 · **来源** US-1106-7 · **模块** 发卡与卡片

**为什么做**：客人预订后到店，房间是「预定房」，前台点右键「发行房间门卡」是灰的，必须先手动改成空净房才能发卡；而且客人姓名在预定里已经填过一次，发卡界面还要再输一遍。

**现状**【核实】：
- `src/pages/RoomManager.tsx` 的 `ISSUABLE_STATUS` 只含 `vacant_clean` / `occupied_partial`，`reserved` 不在白名单，右键菜单发卡项被禁用。
- `IssueForm` 已支持 `initialGuest`（换房路径在用），但常规发卡入口传 `undefined`。
- 后端 `issue_guest` 不按房态拦截（业务铁律：房态只做前端拦截），所以只需改前端。

**改动点**
1. `ISSUABLE_STATUS` 加入 `reserved`（空脏 / 已满 / 维修 / 其他仍禁用）。
2. 新增 `openIssue(room, mode)`：先拉该房覆盖今天的有效预定（`listReservations(today, tomorrow, roomNo)`），取第一条有姓名的，经 `issueGuest` 传给 `IssueForm` 的 `initialGuest`；拉取失败不阻断发卡。
3. 右键「发行房间门卡 / 续住写卡」改走 `openIssue`；换房 move 路径不动（带源房客人信息）。
4. 同步提示文案与 `AGENTS.md` 业务铁律行。

**验收标准**
- [x] 预定房右键可点「发行房间门卡 / 续住写卡」，不再置灰
- [x] 该房有覆盖今天的预定且带姓名时，发卡表单姓名已预填，可改
- [x] 拉预定失败或无预定时发卡不受影响（姓名留空）
- [x] 空脏 / 已满 / 维修 / 其他房仍不能发卡
- [x] `pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：只动前端白名单与入口，后端不改；预定姓名只存库不写卡（卡里只有 8 字节）。
**待拍板**：无
