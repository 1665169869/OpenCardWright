# TD-406 初始房间导入（CSV / ini）

**优先级** P1 · **状态** 已完成 · **来源** RM4 · **模块** 记录与运维

**为什么做**：房号来源应该是「首启一次性导入」，但发布版没有导入入口，只有 debug 下从 `data/NacreHis.json` 自动导 30 间 —— 真实用户装完是空库。

**现状**【核实】：`src-tauri/src/demo_import.rs`（仅 `debug_assertions`）读 `data/NacreHis.json` 的 `Kf_fh`；
`data/RoomIndex.ini` 存在但没人读；没有 CSV 解析。

**改动点**
1. `commands.rs`：`import_rooms_csv(path)` / `import_rooms_ini(path)`，列 `房号,序号?,房型,楼层?`。
2. 冲突策略：房号已存在 → 跳过并计数；序号命中已删房 → 走现有复活规则（`insert_room_reporting`）。
3. 前端：设置 → 房间 →「导入房间」，结束后给「成功 N / 跳过 M / 失败 K（附前 10 行原因）」。

**验收标准**
- [x] 导入 30 行生成 30 间房，序号按规则分配或沿用（单测覆盖表头/引号/自动序号）
- [x] 重复导入幂等（第二次全部 skipped）
- [x] 坏行汇总报错但不中断（`failed: [{line, reason}]`）
- [x] 不依赖 `data/` 目录（前端传字节，后端只认格式）

**依赖 / 风险**：CSV 不要引新 crate（字段简单，手写 split，注意 BOM 与引号）。
