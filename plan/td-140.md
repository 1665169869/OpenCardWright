# TD-140 用原厂 RWCardDemo 抓样本，验证页2 第 4 字节语义

**优先级** P1 · **状态** 已完成 · **来源** US-1106-41 · **模块** 发卡与卡片

**为什么做**：原厂文档证明「退房钟点 `tfzd`（11–18）」「开反锁 `fs`」都是**写卡参数**，而我们的卡把页2
第 4 字节固定写成 `AB`（常量），没有这两个字段的位置。若原厂把它们编码在那一字节，我们发出的卡
在「退房钟点非 12 点」或「需要开反锁」时就与锁的理解不一致。

**做法（需要读卡器 + 原厂包）**
0. **先确认芯片类型（前置）**：用户 2026-11-08 确认现场卡是 **TEMIC（T5557/5567，走 `te_*`）**，
   而本 SDK 的 `LcSDK.ini` 是 `CardType=6` → `em4305_*` 路径（4 块 16 字节）。
   先查 `mif_selecard` 参数含义 / 用读卡器实测哪种命令能读到现场卡。
   **若本 SDK 只能驱动 EM4305**，则它对本项目只作语义参考，`tfzd`/`fs` 在没有 T5557 对应位置前无法落地。
1. 把 `vendor/125k-sdk-v4.2/.../接口文件/` 整个拷到一台装了原厂读写器驱动的机器，
   先用 `SDKAuth.exe` 完成授权（否则读写返回 128）。
2. 用 `RWCardDemo.exe` 写三张卡，逐张读回 8 字节并记录：
   - ① 退房钟点 12 点、1 天、不挂失、不允许反锁（基准）
   - ② 退房钟点 13 点、1 天，其余同①（看钟点位怎么变）
   - ③ 开反锁 = 1，其余同①（看反锁位怎么变）
3. 用我们的 `PMSLockCard.exe issue` 写同样时长的卡，对比 8 字节差异。
4. 若定位到钟点/反锁位，评估是否把 `tfzd` 与 `fs` 加进 `CardBuilder`（**需要改 sdk/，须单独拍板**）。

**验收标准**
- [ ] 三张原厂样本的 8 字节记进 `docs/抓包样本与验证记录.md`
- [ ] 页2 第 4 字节的位含义有明确结论（或标注「仍未知」）
- [ ] 给出「是否把钟点/反锁写进卡」的建议，交用户拍板

**进展（2026-11-08，ida-mcp）**：已用 IDA 反编译原厂写卡链路，**代码层面确认**：
- `tem_writedoorcard13_sdk` 把 `tfzd` 存 `dword_1001FED8`、`fs` 存 `byte_1001FED4`，再调基础版写卡；
- 真正的字节构造在 `sub_10008885`：`tfzd` 编码为 **`tfzd - 11` 的 3 位二进制**（越界按 1=12 点），
  `fs` 是**位串里的 1 个 bit**；字段经 `sub_10002E3C`（整数→二进制串）→ `sub_10002ABD`（反转）
  → `sub_10002767`（串→整数）拼成字节。
- 由此证实：我们的卡**确实没写 `tfzd`/`fs`**；`AB` 不是钟点字段（钟点只占 3 位、跨字节）。
- 还差**位 offset → 卡内字节**的闭合映射（需继续追 `sub_10008885` 的两次调用产出哪页），
  或改走实测（写卡看哪一位翻转）。详细记录见 `docs/原厂SDK-v4.2-分析.md` §7。

**进展补充（2026-11-08，回答「抓包为什么只有 2 页」）**：用户确认现场卡是 **TEMIC（T5557/5567，走 `te_*`）**，
而本 SDK 默认 `CardType=6` → EM4305（4 块 16 字节）。我们串口抓包只看到 2 页 = **T5557 的真实行为**
（`docs/抓包样本与验证记录.md` §8 已记录「只写 2 页，页3 以后完全没动」），不是抓漏。
两套实现的对比、以及 `dword_1002000C` 由 `LcSDK.ini` 决定的证据，见
`docs/原厂SDK-v4.2-分析.md` §9。**因此上面第 0 步（确认芯片）是整条验证的前置条件。**
