# TD-201 右键「预定房间」

**优先级** P1 · **状态** 已完成 · **来源** ST-3 · **模块** 房间与预订

**为什么做**：房态里已经有「预定」，但没有把房间改成预定的入口，只能靠「多选房间」批量改，一个人值班时很别扭。

**现状**【核实】：`app/src/pages/RoomManager.tsx` 的右键菜单（`roomMenu()`）只有 多选房间 / 发行房间门卡 / 续住写卡 / 持卡退房 / 无卡退房 / 删除房间；
`set_room_status` 命令与「预定」房态都已存在，本次不需要新后端。

**改动点（Q-201 已定 A：只改房态，不记时间）**
1. 右键菜单加「预定房间」，位置放在「发行房间门卡」之前，图标沿用现有 Outlined 风格。
2. 点击后调 `set_room_status(room_no, 'booked')`（房态 key 执行时核对 `list_room_statuses` 的返回值）。
3. 确认后刷新房态；是否需要二次确认执行时决定（改房态是低风险操作，倾向不加）。

**验收标准**
- [x] 右键出现「预定房间」，确认后卡片变预定色（房态 key 实为 `reserved`，已就地注释）
- [x] 预定房不能发卡（沿用现有 `ISSUABLE_STATUS` 白名单，不需要额外拦截）
- [x] 房态改动走现有 `set_room_status`，审计行为与批量改房态一致

**依赖 / 风险**：若选 B（带有效期），要 schema 迁移 + 复用 App 的 30 秒轮询做到期回落，改动量放大；带日期方案已另立 TD-202（2026-11-06 用户确认）。
**待拍板**：已定 A（2026-11-06）——只改房态为「预定」，不记预定时间；带有效期的方案另立 TD-202，不在本条扩。
