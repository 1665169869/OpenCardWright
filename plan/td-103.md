# TD-103 发卡页预计退房改 TimePicker

**优先级** P2 · **状态** 已完成 · **来源** ST-5 · **模块** 发卡与卡片

**为什么做**：现在退房时间固定按「入住 + N 天的中午 12:00」推算，前台没法表达「客人要求 14:00 退房」。

**现状**【核实】：`app/src/components/IssueForm.tsx:57` 注释写死「日租按入住当天 + N 天的中午 12:00」，
`:143` 渲染 `预计退房：{startAt} - {checkoutAt}`，`:146` 已有说明「按发卡时间估算……门锁实际从首次刷卡起算」。无任何时间选择控件。

**改动点**
1. 日租增加「预计退房时间」`TimePicker`（默认 12:00），据此换算生效天数。
2. 换算结果仍受 `src-tauri/src/rules.rs` 与 `src/api.ts` 的档位表约束（≥ 1 天、≤ 62 天）。
3. 钟点卡不动。

**验收标准**
- [x] 选 14:00 后展示区间随之变化（跨零点按次日估算并提示）
- [x] 写卡仍是「天数」，卡内字节不因时分变化（`days` 与 `expires_at` 逻辑未动）
- [x] 62 天上限仍被拦截（`dayOptions` / 后端 `validate_days` 未动）
- [x] 界面上保留说明「时间只影响记录与到期估算，锁按首次刷卡起算」

**依赖 / 风险**：最后一条是**必须**的 —— 卡里只有时长码、没有绝对到期时刻（`app/README.md` §6 第 7 条），不写清会变成售后纠纷。
