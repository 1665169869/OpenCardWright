# TD-228 退房（到期）提醒接入系统通知（双管）

**优先级** P1 · **状态** 已完成 · **来源** US-1111-5 · **模块** 记录与运维

**为什么做**：现在的到期提醒只有应用内 antd 通知（`app/src/App.tsx:58/189`），窗口最小化或不在前台时看不到。
用户要求退房提醒走系统通知，让前台在别的窗口操作时也能收到。

## 与 TD-226 的关系

- **TD-226** 修「到点不播报」——声音链路（`speak` / `playAlert`）的问题，先复现再修；
- **TD-228** 加「系统 toast」——可见性链路，依赖 TD-226 的复现结论（避免两条同时改，导致分不清是声音还是通知的问题）；
- 两条**分开验收**：TD-226 看「有没有声音」，TD-228 看「窗口不在前台时有没有弹出」。

## 现状【核实】

- `app/src-tauri/Cargo.toml` 只有 `tauri-plugin-single-instance = "2"`，**没有 notification 插件**。
- `main.rs` 只注册了 single-instance 插件。
- `capabilities/default.json` 没有 notification 权限。
- 前端提醒链路（`App.tsx:180-204`）：`expiring_cards` → `notification.warning(...)`（antd，应用内）+ `speak` / `playAlert`。
- WebView2 **不实现** Web Notifications API，不能用 `new Notification()`，必须走 Tauri 插件。

## 改动点

1. **依赖**：`app/src-tauri/Cargo.toml` 加 `tauri-plugin-notification = "2"`；`main.rs` 注册
   `.plugin(tauri_plugin_notification::init())`；`app/package.json` 加 `@tauri-apps/plugin-notification`。
2. **权限**：`capabilities/default.json` 加 `"notification:default"`（必要时细化为 `allow-notify` / `allow-request-permission`）。
3. **前端封装**：新增 `app/src/utils/notify.ts`：
   - `ensureNotifyPermission()`：`isPermissionGranted()` → `requestPermission()`，缓存结果；
   - `systemNotify(title, body)`：`sendNotification({ title, body })`，失败 / 拒绝返回 `false`；
   - 全部包 `try/catch`，不把异常抛给提醒轮询。
4. **提醒链路**（`App.tsx`）：每条新记录先 `systemNotify(...)`；系统通知不可用（权限拒绝 / 非 Tauri 环境）时
   保留应用内 `notification.warning`；两者都发时内容一致（房号 + 卡型 + 到期时间）。
   首次失败只记一条 `log_frontend`，避免每次轮询刷日志。
5. **设置项**：沿用现有 `reminderEnabled`，不新增开关（系统通知与应用内通知一起受控）。

## 验收标准

- [ ] 首次触发提醒时弹出系统通知权限请求；允许后 Windows 通知中心能看到 toast
- [ ] 应用最小化 / 不在前台时，到点仍能收到系统通知
- [ ] 拒绝通知权限时，应用内通知照常工作，并在界面上有一次可见提示（说明系统通知被拒）
- [ ] 应用内通知与系统通知内容一致（房号 / 卡型 / 到期时间）
- [ ] `cargo check`、`pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过

## 待拍板

## 依赖 / 风险

- 依赖 TD-226 的复现结论：先确认「没声音」的根因，再叠加系统通知，避免互相干扰。
- `tauri-plugin-notification` 需要 capability 权限；忘记加会在运行时报 denied，**构建期不报错**。
- Windows 通知需要系统「通知和操作」允许该应用；被系统级关闭时只能回退应用内通知（验收时要区分）。
