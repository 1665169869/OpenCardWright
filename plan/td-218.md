# TD-218 挂失卡发行后自动作废同房有效客卡

**优先级** P1 · **状态** 待办 · **来源** US-1109-11 · **模块** 发卡与卡片

**为什么做**：客人报失后，前台会勾选「挂失卡」再发行一张挂失卡。门锁侧会因卡内挂失位让旧卡失效，
但数据库里的旧客卡记录仍被视为有效，房间「有效卡」数量、续住/换房默认数据、日历统计都不正确。
用户要求挂失卡发行成功后，自动把同房有效客卡标记为失效并移除有效卡标记。

## 现状

- `IssueForm` 已有「挂失卡（让本房间在用卡失效）」勾选。
- `issue_guest` 在勾选时把 `--lost` 传给 CLI，卡内 `页1[2]` 低 4 位 = 1。
- 数据库 `issuance` 没有单独的挂失/作废字段；只区分：
  - `result = 'ok'` / 失败；
  - `checked_out_at`：退房时间；
  - `expires_at`：按发卡时间估算的到期时间。
- `count_active_cards` / `latest_active_guest_card` 仍按：
  `result='ok' AND checked_out_at IS NULL AND expires_at > now` 统计。
- 因此挂失卡只影响门锁侧水位，数据库旧客卡仍显示有效，日历/房间卡片的「有效卡」不会自动减少。

## 期望

- 挂失卡**写卡成功后**，同一事务内把同房、客卡、仍有效、未退房的记录标记为失效。
- 失效记录不再计入：
  - `activeCards` / 有效卡数；
  - `latest_active_guest_card`；
  - 房间「有效卡」标记、续住/换房默认数据、日历入住统计。
- 挂失卡本身保留发卡记录与审计，但不应作为普通有效客卡计数。
- 写卡失败时不能改任何旧记录；只有实际写卡成功后才执行失效。
- 审计记录增加：作废记录数、房号、挂失卡记录 id。

## 改动点

- [ ] 新增失效字段（建议 `invalidated_at` / `invalid_reason`），保留退房与作废的不同语义。
- [ ] 挂失卡写卡成功后，更新同房有效客卡：
  - 只处理 `kind IN ('日租客卡','钟点客卡')`；
  - 只处理 `result='ok'`、`checked_out_at IS NULL`、未过期、未被作废的记录；
  - 不处理挂失卡自身、管理卡、已退房记录。
- [ ] `count_active_cards`、`latest_active_guest_card`、有效卡列表/房间统计统一排除已作废记录。
- [ ] `issue_guest` 返回作废数量，前端提示「已作废 N 张同房有效卡」。
- [ ] 写卡失败时回滚/不执行失效更新；审计记录失败原因。
- [ ] 日历入住色块、房间卡片有效卡标记、续住/换房默认数据同步使用新口径。

## 验收标准

- [ ] 同房有 2 张有效客卡，勾选挂失卡发行成功后：
  - 旧 2 张记录标记为失效；
  - `activeCards` 变为 0（挂失卡不计入普通有效卡）；
  - 房间「有效卡」标记消失；
  - 续住/换房不再带出旧卡客人。
- [ ] 写卡失败时旧记录仍有效，统计不变。
- [ ] 挂失卡自身保留发卡记录与审计，但不出现在普通有效卡列表。
- [ ] 已退房记录不被二次标记为“挂失作废”。
- [ ] 普通发卡（未勾选挂失）行为不变。
- [ ] `cargo test --workspace`、`pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过。

## 数据模型待拍板

- **方案 A（建议）**：新增 `invalidated_at` / `invalid_reason`，能区分“退房”“挂失作废”“其他作废”，历史完整。
- **方案 B**：复用 `checked_out_at`，把挂失作废当退房；改动最小，但退房与作废语义混淆。
- **方案 C**：只加 `is_lost` 标记并让统计过滤挂失卡；无法表达旧卡被作废的时间。

建议采用方案 A；若选 B/C，需要同步调整报表和审计口径。
