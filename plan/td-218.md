# TD-218 挂失卡发行后自动作废同房有效客卡

**优先级** P1 · **状态** 已完成 · **来源** US-1109-11 · **模块** 发卡与卡片

**为什么做**：客人报失后，前台会勾选「挂失卡」再发行一张挂失卡。门锁侧会因卡内挂失位让旧卡失效，
但数据库里的旧客卡记录仍被视为有效，房间「有效卡」数量、续住/换房默认数据、日历统计都不正确。
用户要求挂失卡发行成功后，自动把同房有效客卡标记为失效并移除有效卡标记。

## 现状（登记时）

- `IssueForm` 已有「挂失卡（让本房间在用卡失效）」勾选。
- `issue_guest` 在勾选时把 `--lost` 传给 CLI，卡内 `页1[2]` 低 4 位 = 1。
- 数据库 `issuance` 没有单独的挂失/作废字段；`count_active_cards` / `latest_active_guest_card`
  只按 `result='ok' AND checked_out_at IS NULL AND expires_at > now` 统计。
- 因此挂失卡只影响门锁侧，数据库旧客卡仍显示有效。

## 期望

- 挂失卡**写卡成功后**，同一事务内把同房、客卡、仍有效、未退房的记录标记为失效。
- 失效记录不再计入 `activeCards` / 有效卡数 / `latest_active_guest_card` / 日历入住统计。
- 挂失卡本身保留发卡记录与审计，但不应作为普通有效客卡计数。
- 写卡失败时不能改任何旧记录；只有实际写卡成功后才执行失效。
- 审计记录增加：作废记录数、房号、挂失卡记录 id。

## 改动点

- [x] 新增失效字段（`invalidated_at` / `invalid_reason`），保留退房与作废的不同语义。
- [x] 挂失卡写卡成功后，更新同房有效客卡：
  - 只处理 `kind IN ('日租客卡','钟点客卡')`；
  - 只处理 `result='ok'`、`checked_out_at IS NULL`、未过期、未被作废的记录；
  - 不处理挂失卡自身、管理卡、已退房记录。
- [x] `count_active_cards`、`latest_active_guest_card`、房间列表内联 `active_cards` / `active_until`、
      到期提醒、退房查询、raw 匹配排序统一排除已作废记录。
- [x] `issue_guest` 返回作废数量，前端提示「已作废 N 张同房有效卡」。
- [x] 写卡失败时不执行失效更新（作废调用在 `record_issuance` 成功之后）。
- [x] 日历入住色块、房间卡片有效卡标记、续住/换房默认数据同步使用新口径。

## 完成形态（2026-11-10）

- schema **v13**（`apply_v13` + `schema.sql` 同步）：`issuance.invalidated_at` / `invalid_reason`，
  另建 `idx_issuance_invalidated`；`SCHEMA_VERSION` 12 → 13。
- `ocw_store::invalidate_guest_cards(conn, room_no, new_card_id)`：
  旧卡 `invalid_reason='lost'`，挂失卡本人 `invalid_reason='lost_card'`（两者都写 `invalidated_at`），
  返回旧卡张数。
- `commands.rs::issue_guest`：写库后、房态同步前调用；`IssuedDto.invalidated` 随结果返回；
  房态升级加 `after > 0` 保护，避免挂失后有效卡归零被误标成「未满房」。
- 前端：`IssuedCard.invalidated` + 发卡结果里的警告 Alert。

## 验收标准

- [x] 同房有 2 张有效客卡，勾选挂失卡发行成功后：
  - 旧 2 张记录标记为失效 —— 单测 `invalidate_guest_cards_skips_closed_records` 断言 `n == 2`；
  - `activeCards` 变为 0（挂失卡不计入普通有效卡）—— 同上断言 `count_active_cards == 0`；
  - 房间「有效卡」标记消失 —— `ROOM_SELECT` 的两个子查询都排除 `invalidated_at`；
  - 续住/换房不再带出旧卡客人 —— `latest_active_guest_card` 返回 `None`。
- [x] 写卡失败时旧记录仍有效，统计不变 —— 作废调用位于 `record_issuance` 成功之后。
- [x] 挂失卡自身保留发卡记录与审计，但不出现在普通有效卡列表。
- [x] 已退房记录不被二次标记为“挂失作废” —— 单测断言该记录 `invalid_reason IS NULL`。
- [x] 普通发卡（未勾选挂失）行为不变 —— `invalidated` 恒为 0，不触碰任何旧记录。
- [x] `cargo test --workspace`、`pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过。

## 数据模型结论

已定：**方案 A** —— 新增 `invalidated_at` / `invalid_reason`，能区分「退房」「挂失作废」「挂失卡本身」，
历史完整；未采用复用 `checked_out_at`（方案 B）或只加 `is_lost`（方案 C）。
