# TD-215 BUG：日历不显示已退房/历史入住记录

**优先级** P1 · **状态** 待办 · **来源** US-1109-8 · **模块** 房间与预订

**为什么做**：日历现在只显示仍有效的入住色块，客人退房后记录就消失；用户要求日历同时展示预定状态、
在住状态和已退房状态，便于回看历史与跨月长期入住。

## 现状

- `RoomCalendar` 加载入住色块时直接跳过：
  - `r.checkedOutAt !== null`（已退房）；
  - `!r.expiresAt`（没有到期时间）；
  - `Date.parse(r.expiresAt) <= now`（已过期）。
- 因此 4 号入住、5 号退房的客人，在 5 号之后日历里不再显示 4→5 的入住记录。
- 长期入住 `11-5 → 12-5` 若中途 `11-20` 退房，卡片仍在，但日历按 `expiresAt` 或直接不显示，
  无法表达“实际住到 11-20”。
- 当前只拉 `pageSize: 200` 的两类客卡，历史记录较多时可能被截断。

## 期望

- 日历同时显示：
  - 预定：`booked` 色块；
  - 在住：有效客卡色块；
  - 已退房：历史入住色块（可弱化颜色/加「已退房」标识）。
- 入住区间的终点应区分：
  - `expiresAt`：原计划到期时间；
  - `checkedOutAt`：实际退房时间；
  - 已退房时按 `checkedOutAt` 截断，未退房时按 `expiresAt`。
- 例子 1：4 号入住、5 号退房，今天 5 号仍显示 4→5 的入住记录。
- 例子 2：11-5 到 12-5 的长期入住，中途 11-20 退房，日历显示 11-5→11-20，而不是到 12-5。
- 查询范围应覆盖当前日历可见月份（含前导/溢出列），不能只靠最近 200 条。
- 预定色块与入住/已退房色块分层显示，不互相遮挡点击。

## 改动点

- [ ] 调整 `RoomCalendar` 的入住记录过滤：不再无条件排除 `checkedOutAt`，改为按日历可见区间筛选。
- [ ] 计算实际入住区间：`start = createdAt`，`end = checkedOutAt ?? expiresAt`。
- [ ] 区分状态样式：在住 / 已退房 / 已过期，至少用颜色或角标区分。
- [ ] 查询改为按日历区间拉取，或提高分页并明确截断规则；不能固定只取 200 条。
- [ ] 处理跨月：11-5→11-20 与 11-5→12-5 都要能跨月显示。
- [ ] 保持现有预定色块逻辑不变，仅扩展入住/已退房色块。
- [ ] 点击已退房色块显示实际退房时间、原计划到期时间、客人信息。

## 验收标准

- [ ] 已退房记录在对应日期仍可见（至少保留可回看范围）。
- [ ] 4 号入住、5 号退房的记录在 5 号视图显示 4→5。
- [ ] 11-5→12-5 的长期入住中途 11-20 退房后，显示 11-5→11-20。
- [ ] 跨月长期入住不因只取最近 200 条被截断。
- [ ] 预定色块与入住/已退房色块不互相遮挡，点击行为正确。
- [ ] `cargo test --workspace`、`pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过。

## 待拍板

- 已退房色块是否需要弱化显示？建议灰色或加「已退房」角标，避免与在住混淆。
