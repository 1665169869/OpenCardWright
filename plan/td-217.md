# TD-217 修改预定信息时允许修改房间号

**优先级** P2 · **状态** 已完成 · **来源** US-1109-10 · **模块** 房间与预订

**为什么做**：客人改房或前台排房调整时，需要把已有预定从 A 房改到 B 房；目前编辑预定只能改日期、
姓名、备注，房间号被锁定，只能取消后重订。

## 现状

- 前端 `ReservationModal` 的 `targetRoomNo` 直接取 `editing?.roomNo ?? room?.roomNo ?? ''`，
  编辑模式没有房间选择控件，房号固定。
- 后端 `ocw_store::update_reservation` 已经接收 `room_no`，并会在改房时：
  - 校验旧房 / 新房启用状态；
  - 校验同房预定重叠；
  - 同步旧房与新房覆盖今天的房态；
  - 允许改日期、房号、客人信息、备注。
- 因此主要缺口是前端改房入口、房间列表筛选、成功/失败提示与验收。

## 改动点

- [ ] `ReservationModal` 编辑模式增加「目标房间」选择器，默认当前房号。
- [ ] 房间列表只列启用房间；显示房号、房型、当前房态；当前房号保持可选。
- [ ] 新建模式保持现有 `room` 目标，不改变现有入口。
- [ ] 保存时调用 `updateReservation(id, { roomNo: 新房间, ... })`；日期/客人/备注字段保持。
- [ ] 改房失败（目标房已有重叠预定、目标房不存在/停用、后端校验失败）时保留表单内容，不关闭弹窗。
- [ ] 改房成功后刷新日历/房间列表，并提示「预定已从 A 房改到 B 房」。
- [ ] 旧房房态释放、新房房态占用由现有后端 `sync_room_status_for_reservation` 负责；前端不重复改房态。
- [ ] 房态提示：改到维修/其他/已满房时给出提示，但最终以重叠校验和房态规则为准。

## 验收标准

- [ ] 编辑预定时可把房间从 A 改成 B，保存后日历上 A 房色块消失、B 房色块出现。
- [ ] 改到空房成功；改到已有重叠预定的房号被拒绝，弹窗保持打开且原表单不丢。
- [ ] 改到已停用/不存在房号被拒绝，提示明确。
- [ ] 原房覆盖今天的房态正确释放；新房覆盖今天时正确标为预定房。
- [ ] 日期、入住/退房时间、客人姓名、备注在改房后保持不变。
- [ ] 新建预定的流程与现有行为不变。
- [ ] `cargo test --workspace`、`pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过。
