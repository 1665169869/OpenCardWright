# TD-223 日历入住详情支持编辑（打开登记表单）

**优先级** P1 · **状态** 已完成 · **来源** US-1111-2 · **模块** 房间与预订

**为什么做**：日历点入住色块弹出的详情（TD-120 / TD-221）是**纯只读**的，看到住客信息有问题只能去房间右键
或记录页再找一遍。用户要求：点详情后能直接修改入住信息、状态等。

## 现状【核实】

- `RoomCalendar` 的入住详情弹窗（`app/src/components/RoomCalendar.tsx:703` 起）由 `stayDetail` 驱动：
  头部 `Descriptions` + 住客下拉（TD-221），`footer={null}`，**没有任何编辑入口**。
- 点色块时已经按 `checkinId` 调 `api.getCheckin` 加载住客，数据就在前端。
- 可复用的编辑界面已有：`CheckinForm`（`app/src/components/CheckinForm.tsx`）。

## 改动点

1. `CheckinForm` 增加可选 `checkinId` 属性：传入时**直接加载该登记单**（不调 `create_checkin`），
   用于从日历详情进入编辑；不传时保持现有「按房号建单 / 复用 open 单」行为。
2. 日历详情弹窗 `footer` 加「编辑登记」按钮（`checkinId` 为空的历史记录不显示）：
   打开 `CheckinForm`（带 `roomNo` 与 `checkinId`）；保存 / 关单后重新 `api.getCheckin` 刷新详情，
   并触发日历重拉（`reloadToken`）。
3. 「状态」修改：登记单只有 `open` / `closed`，通过「关闭登记单」切换；住客级状态不引入（当前模型没有）。
4. 全部复用现有登录级命令，**不新增后端命令**。

## 验收标准

- [ ] 日历点色块 → 详情 →「编辑登记」能打开登记表单，并预载该单全部住客
- [ ] 修改住客、增删人、关闭登记单后，详情与日历立即刷新
- [ ] 从日历进入编辑不会新建空单（复用传入的 `checkinId`）
- [ ] 没有登记单的历史入住（`checkinId` 为空）不显示「编辑登记」，行为不变
- [ ] `pnpm exec tsc --noEmit`、`pnpm exec vite build` 通过
