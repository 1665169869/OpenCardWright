# TD-126 退房钟点成为设置项 + 日租卡到期按「退房日 + 钟点」写库

**优先级** P1 · **状态** 已完成 · **来源** US-1106-26 · **模块** 发卡与卡片

**为什么做**：退房钟点（checkout hour）此前**不是设置项**——发卡页「预计退房时刻」与
管理卡「退房钟点卡」各用一个本地 `useState`（默认 12，改完不记忆、两处互不相通），
而写库的 `expires_at` 走「开卡时刻 + N 天」顺延：18:00 开 1 天卡 → 日历/记录都显示次日 18:00
到期，与业务上的「次日 12:00 退房」不一致。用户要求：退房钟点做成设置项、显示与写库都按它算。

**现状**【核实】：
- `AdminCards.tsx` 退房钟点 = `useState(12)` 现填；`IssueForm.tsx` 预计退房 = `useState('12:00')` 硬默认；两处都不读设置。
- `ocw-store::record_issuance` 的 `expires_at = created_at + N 天`（`expiry_modifier` 顺延），18:00 开卡即次日 18:00。

**改动点**
1. 设置项：`get_checkout_hour`（Login）/ `set_checkout_hour`（Admin），存 `setting` 表的
   `checkoutHour`（默认 12、0–23 校验）；MATRIX 登记使命令总数 69 → **71**（login 29 / admin 36），
   `README` §8 表同步；`api.ts` 封装 `getCheckoutHour` / `setCheckoutHour`。
2. 写库：`record_issuance` 对**日租客卡**（days > 0）把 `expires_at` 改为「本地开卡日 + N 天」的
   `checkoutHour:00`（18:00 开 1 天 → 次日 12:00）；钟点卡/管理卡仍按 `expiry_modifier` 顺延；
   **卡内时长码与锁的实际判定不变**。修复 SQLite 修饰符双转换（原写法 `unixepoch(...,'localtime'),'unixepoch'`
   实测把本地 6 点算成 22 点，改直接 `'utc'`），新增回归用例 `guest_day_expiry_uses_checkout_hour_setting`。
3. 前端：设置页新增「退房钟点」面板（0–23、保存反馈、影响说明）；发卡页「预计退房时刻」读设置、
   改**只读**展示；管理卡页「退房钟点」只读展示设置值 + 「要改去设置页」引导，发卡传设置值
   （后端 `AdminCardRequest::Checkout` 签名不动）。
4. 记录页「到期」列不改（**拍板**：语义偏「卡实际失效」，保持真实 `expires_at`）。

**验收标准**
- [x] 设置页可改退房钟点（0–23，默认 12），保存后发卡页与管理卡页同步显示
- [x] 日租卡 18:00 开 1 天 → `expires_at` = 次日 12:00；改设置 6 点后新卡次日 06:00
- [x] 钟点客卡/管理卡仍按发卡时刻顺延（回归用例覆盖）
- [x] 发卡页与管理卡页退房钟点均只读 + 设置页引导
- [x] `cargo test --workspace` **120 项全绿**；`pnpm exec tsc --noEmit` 通过；README §8 71 条与 MATRIX 一致

**依赖 / 风险**：卡内时长码不变，软件 `expires_at` 与锁的实际失效时刻可能有偏差（锁日界语义 docs
仍【待定】：05:00 开 1 天卡，锁可能次日 05:00 就拒，软件显示次日 12:00，**最多宽松 7 小时**；
18:00 开卡则软件比锁严 6 小时，安全方向）。历史数据不回溯。
