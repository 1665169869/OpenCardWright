# TD-146 分析 `tem_writedoorcard13WithRec_sdk`（带记录写卡）用途

**优先级** P3 · **状态** 待办 · **来源** US-1106-42 · **模块** 发卡与卡片

**为什么做**：DLL 里有两个导出是文档没提的：`tem_writedoorcard13WithRec_sdk`、`tem_writedoorcardWithRec_sdk`。
「WithRec」暗示写卡时**同时写一条记录**——可能是卡内记录区（门锁后来可回读开锁历史），也可能是软件侧日志。
若是卡内记录区，我们完全没利用；若只是软件侧，与我们 `issuance` 表思路一致，无需改。

**现状**【核实】：两个函数都在导出表里（`dumpbin /EXPORTS`，ordinal 0x4E / 0x50），且都引用
`dword_1001FED8`（tfzd）与 `byte_1001FED4`（fs）——说明它们也是 13 版写卡路径。

**改动方向**
1. IDA 反编译这两个函数，对比 `tem_writedoorcard13_sdk` 的差异（多出的参数/多写的目标）；
2. 判断记录写到卡内还是软件侧；
3. 若在卡内，评估是否需要读取（读卡页是否要展示开锁记录）。

**验收标准**
- [ ] 明确「记录写到哪」的结论（卡内 / 软件侧 / 待验证）
- [ ] 若卡内有记录区，给出读取方式与字段结构

**依赖 / 风险**：需要 IDA（与 TD-141 同一套分析环境）；可能牵扯卡内存储布局。
