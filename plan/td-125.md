# TD-125 凌晨（00:00–06:00）入住归属前一晚（只改日历展示，退房时刻可配）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-25 · **模块** 房间与预订

**为什么做**：酒店惯例是房晚归属——凌晨 00:00–06:00 办理入住算**前一晚**的订单。示例：客人 11-05 05:00 入住 → 订单归属 11-04，退房 11-05 12:00，日历房态显示「入住 11-04、退房 11-05」。当前日历按发卡时刻的自然日显示，凌晨入住被算成当天，与客人/前台理解的「住哪晚」不一致。

**现状**【本轮已核实】：
- 日历入住色块 = `localDay(created_at) → localDay(expires_at)`（`RoomCalendar.tsx` 174–175 行，`guestSpans` 拉取时取本地日）——05:00 发的卡按发卡日显示，不归前一晚。
- `expires_at = created_at + N 天`（`ocw-store lib.rs:1293`，`strftime(created_at, ?1)` 参数化 modifier）。
- 卡的**物理失效由锁按时长码 + 锁内时钟判定**，数据库 `expires_at` 只是软件镜像；**锁的日界语义在 docs 里是【待定】**（技术规格 522 行待验证项「锁内卡记录是否会按天重置」）。
- 设置页无「退房时刻」配置项。

**拍板（2026-11-07）**
1. **只改日历展示**：色块 / 入住详情显示归属日区间；`created_at`、`expires_at`、发卡记录、到期提醒、卡内数据**全不动**（零后端）。
2. **退房时刻 N 可配置**：设置页加「退房时刻」，默认 **12:00**。
3. 边界：**06:00 整归当日**（00:00–05:59 归前一晚）；**仅日租客卡**（钟点卡小时制不适用，管理卡无关）；预定不受影响（未来日期无凌晨概念）；历史数据不回溯。

**改动点（方向）**
1. 归属日 helper（前端）：`localDay` 时刻 <06:00 → 归属日前移一天。
2. `guestSpans` 起止改归属区间：`start = 归属日`、`end = 归属日 + N 天`（N = 发卡时长折算），色块显示 11-04→11-05。
3. 入住详情 Modal 退房时刻用配置 N（默认 12:00）；发卡记录原始时刻保留展示。
4. 设置页新配置项「退房时刻」（默认 12:00，存 `setting` 表）。

**验收标准**
- [ ] 11-05 05:00 发 1 天卡 → 日历显示 11-04→11-05、详情退房 11-05 12:00
- [ ] 06:00 后发卡显示「当日 → +N」；钟点卡 / 管理卡不受影响
- [ ] 发卡记录原始时刻不变；改 N（如 14:00）后详情随之变化
- [ ] `pnpm exec tsc --noEmit` + `cargo test --workspace` 通过

**依赖 / 风险**：只动展示层零后端；日历退房时间与卡实际失效时刻可能差几小时（**已接受**——拍板只改展示；锁内实际日界待现场验证）。
