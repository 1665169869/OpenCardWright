# TD-152 其余管理卡字段逐项复核

**优先级** P3 · **状态** 待办 · **来源** US-1106-45 · **模块** 发卡与卡片

> **2026-11-08 降级原因（用户反馈）**：`RWCardDemo` 的卡型下拉只有「时钟卡」和「写客卡」两项，
> **没有复位/清除/安装/总控的写卡入口**，「用 demo 对照字节」这条路走不通。要先看 SDK 导出
> 有没有对应函数，才谈得上复核。

**为什么做**：这一轮已经查出两处「看起来对、其实错」的字段（`页2[3]` 是年+月不是日期、
`页1[2]` 低 4 位是挂失不是「天数 mod 4」）。**其余管理卡的字节是否也有同类偏差，需要逐项核对**，
不能默认「能用就对了」。

**现状**【待核实，逐项列】：

| 卡型 | 我方字节 | 需要确认的点 |
|---|---|---|
| 复位卡 | `5BEC 0A 00` / 页2 零 | `0x0A` 是什么（序号？固定标记？）；卡号字段为何是 0 |
| 清除卡 | `5BEC 9B E5` + 页2 `C7` | 两个魔数是否有物理含义（原厂做法 vs 我们照抄） |
| 安装卡 | 页2 固定 `46 F2 00 01` | 「最大发卡数」是否就存在这 4 字节里（用户怀疑此处） |
| 总控卡 | 页1 `5BEC F0 FF` | `FF` 是否编码了有效期档位/权限范围 |
| 退房钟点卡 | 页1 `5BEC 7B <钟点>` | `0x7B` 与钟点的关系 |

**改动点**
1. **先查 SDK 导出**：`dumpbin /EXPORTS LCRFRW_SDK.dll` 里是否有「写复位 / 写清除 / 写安装 / 写总控」的专用函数
   （已知只有 `tem_writedoorcard_sdk`、`tem_writedoorcard13_sdk`、`tem_writetimercard_sdk`，
   管理卡可能走别的机制，甚至只由主软件私有实现）；
2. 若 SDK 支持 → 调它或 IDA 反编译，拿到原厂字节与我们逐字节对比；
3. 若 SDK 也不支持 → 改走「反编译主软件」或**接受现状**（我们的字节目前实测都能用）；
4. 对不一致项反推编码，能解出的写进技术规格；无法解出但确认可用的，标注「照抄，含义未定」。

**验收标准**
- [ ] 5 种管理卡各有「原厂 vs 我方」字节对照表进 `抓包样本与验证记录.md`
- [ ] 一致项标注 ✅，不一致项给出原因或「待定」
- [ ] 若发现错字段，同步修 `CardBuilder` 与 selftest 向量
