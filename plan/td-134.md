# TD-134 dev 日志连续报「two children with the same key」（key=0，12 次）

**优先级** P2 · **状态** 已完成 · **来源** US-1106-36 · **模块** 前端

**为什么做**：2026-11-07 跑 `pnpm tauri dev` 验证备份修复时，前端控制台连续 12 次报 React key 重复
（消息里 key 值是 `0`），怀疑某个列表用了非唯一 key。

**根因**【核实】：React 的 key 唯一性不仅对数组元素生效，**同级的兄弟节点也必须唯一**。`RoomManager`
的返回体里两个兄弟组件都用「自增计数器」当 key 且初始值都是 `0`：

```tsx
<ReservationModal key={reserveSession} … />   // 初始 0
<CheckoutCardModal key={checkoutSession} … /> // 初始 0
```

于是每次渲染都报「two children with the same key, 0」——房间页刷新频率高，日志被刷成 50+ 条。

**改动点**
1. 两个 key 加来源前缀：`` key={`reserve-${reserveSession}`} `` / `` key={`checkout-${checkoutSession}`} ``，
   保持「每次打开重新挂载」的原有语义，同时全局唯一。
2. 顺带清掉 dev 日志里剩下的 antd 弃用告警：`ReservationModal` 的 `destroyOnClose` → `destroyOnHidden`。

**验收标准**
- [x] dev 启动并渲染房间页，控制台不再出现 `two children with the same key`
- [x] `pnpm exec tsc --noEmit` 通过
- [x] `ReservationModal` 不再报 `destroyOnClose` 弃用告警

**依赖 / 风险**：纯前端 key 修正，不改数据结构与交互；「每次打开重新挂载」的语义保持不变
（计数器仍在自增，只是 key 字符串带前缀）。
**待拍板**：无
