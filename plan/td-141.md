# TD-141 IDA 静态闭合「位串 → 8 字节」映射

**优先级** P1 · **状态** 已完成· **来源** US-1106-42 · **模块** 发卡与卡片

**为什么做**：TD-139 已把原厂写卡链路反编译到 `sub_10008885`，确认了 `tfzd` 编码为 `tfzd-11` 的 3 位二进制、
`fs` 是位串里 1 个 bit，但**「位 offset → 卡内字节」还没闭合**。这一步不需要读卡器、不需要改任何代码，
纯 IDA 就能做完，而且 TD-142 / TD-144 / TD-146 都依赖它的结论。

**现状**【核实】
- `tem_writedoorcard13_sdk`（0x1000cade）：`tfzd → dword_1001FED8`、`fs → byte_1001FED4`、`dword_1002000C = 3`
- 字节构造在 `sub_10008885`（0x10008885–0x100098e6，反编译体 9191 字符），两条分支分别写 `v27[1]+5`（fs）
  与 `v27[2]+5`（tfzd，3 位）
- 转换原语：`sub_10002E3C`（整数 → n 位二进制串，低位先出）、`sub_10002ABD`（反转）、`sub_10002767`（串 → 整数，串尾 = bit0）

**改动方向**
1. 定位 `sub_10008885` 的**两次调用点**（哪次产出页1、哪次产出页2），以及 `mif_write` / `em4305_write`
   收到的 8 字节来自哪个缓冲。
2. 建立「位 offset → 卡内 byte/bit」的完整映射表，覆盖：`tm_hour`、`tm_mday`、`tm_mon`、`tm_wday`、年、
   `xh`、`sjdw`、`sjlength`、`gs`、`tfzd`、`fs`。
3. 与我们的卡格式（`页1 = 5B EC | ((序号&0x0F)<<4|低4) | (序号>>4)`、`页2 = 时长码|卡号低|卡号高|AB`）做逐位对照。

**产出物**：`docs/原厂SDK-v4.2-分析.md` **新增 §8「位 offset → 卡内字节对照表」**（含两页每 bit 归属与
我们卡格式的映射差异）。

**验收标准**

      `v28`/`v29`/`v30`/`v13` 属 ini 配置项，未取具体值）
- [x] 明确指出 `AB`（页2 第 4 字节）不是钟点字段：钟点在明文层是 `v51[8]` 的 bit5–7，且要过扰码层
- [x] 结论逐条标注证据等级（【反编译】/【推断】/【待验证】）
