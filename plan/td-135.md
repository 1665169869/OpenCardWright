# TD-135 接入华视身份证读卡器（WebSocket 9001）

**优先级** P1 · **状态** 已完成 · **来源** US-1106-37 · **模块** 发卡与卡片

**为什么做**：开卡时手工抄姓名/证件号又慢又错。用户要求接入华视身份证读卡器，开卡页一键读证并回填。

**设备关系**【核实】：身份证读卡器与发卡用的 125 kHz 读卡器是**两个独立设备**——后者经
`PMSLockCard.exe` 子进程走串口，前者由厂商服务提供本机 WebSocket。协议（用户确认）：
**连上即推送，无需发命令**。

**拍板**：实现位置选**前端直连**（用户指定）。因此要放开 CSP，且超时/重试逻辑放在前端。

**改动点**
1. `src/idcard.ts`（新）：`readIdCard(timeoutMs = 8000)` 连 `ws://127.0.0.1:9001`，等第一条含身份证字段的
   推送就 resolve 并关闭连接（不常驻，避免与厂商服务抢端口）。字段做**宽容归一**：
   - 键名兼容英文 / 拼音缩写 / 中文（`name|姓名|xm`、`sex|gender|xb`、`nation|民族|mz`、
     `birth|csrq|出生日期`、`address|住址|dz`、`idno|gmsfhm|身份证号`），并解包 `data|result|info` 外层
   - 出生日期 `19900101` / `1990/1/1` → `YYYY-MM-DD`；性别 `M/F/1/2` → `男/女`
   - 非 JSON、空壳、心跳一律忽略并继续等；连不上 / 主动断开 / 超时都抛中文说明的 Error
2. `tauri.conf.json`：CSP 的 `connect-src` 追加 `ws://127.0.0.1:9001`（不加会被 CSP 拦）。
3. `src/components/IssueForm.tsx`：客人区顶部加「读取身份证」按钮（loading 态）。读成功后
   `setGuest({...guest, ...info, idType: '身份证'})`；失败用受控 `<Alert>` 显示原因（**不用**命令式
   `message`，遵守 React 19 约束），并且**不影响手填与发卡**。
4. 文档：README「已实现」加一条（含改地址要同步改 CSP 的提示）、使用手册 §3.1 加使用说明。

**验收标准**
- [x] 点「读取身份证」→ 服务在跑时自动填 6 个字段，证件类型固定「身份证」
- [x] 服务没起 / 超时 / 中途断开 → 中文提示，表单可继续手填发卡
- [x] 与发卡读卡器互不影响（不占用串口、不触发 `PMSLockCard.exe`）
- [x] `pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：依赖厂商服务占 9001 且**连上即推送**；若实际版本需要先发读卡指令，只需在
`readIdCard` 的 `onopen` 里补一条 send。推送字段名未在真机核对（本机无该读卡器），
归一表按常见版本写宽——真机跑一次若字段没进表，把原始报文加进 `ALIASES` 即可。
