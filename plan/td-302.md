# TD-302 无卡退房后到期提醒不消除

**优先级** P1 · **状态** 已完成 · **来源** US-1106-5 · **模块** 提醒与通知

**为什么做**：前台选择「无卡退房」后，顶栏到期铃铛仍显示该房间的卡，必须等卡自然过期出窗才消失；这会让前台误以为退房没成功，反复操作。

**现状**【核实】：
- `ocw-store/src/lib.rs:1016` `expiring_cards` 的 `latest` CTE 和外层查询都只按 `expires_at` 过滤，**没有 `checked_out_at IS NULL`**。
- `checkout_room`（`ocw-store/src/lib.rs:663`）会把该房 `expires_at > now` 的客卡标记 `checked_out_at`，但提醒查询不看这个字段，所以已退房的卡仍返回。
- App 每 30 秒轮询 `expiring_cards`（`src/App.tsx:142`），查询结果不消除，铃铛就一直存在。

**改动点**
1. `expiring_cards` 外层加 `AND i.checked_out_at IS NULL`；`latest` CTE 保持「取最新一条成功客卡」，避免已退房后回退到更早的过期卡。
2. 补存储层用例：插入一张即将到期客卡 → 退房 → `expiring_cards` 不再返回。
3. `checkout_room` 的 `closed` 计数仍只数仍有效的卡，但额外把该房**已过期未标记**的客卡也标记 `checked_out_at`，避免提醒窗口 `[-1 天, +N 分钟]` 里残留。

**验收标准**
- [x] 无卡退房后，下一次 30 秒轮询 `expiring_cards` 不再包含该房已退房卡
- [x] 已过期但仍在提醒窗口的客卡，退房后也被标记 `checked_out_at`，铃铛不再显示
- [x] `cargo test -p ocw-store` 新增用例通过，原 `checkout_closes_cards_and_marks_room_dirty` 仍通过
- [x] 未退房且即将到期的卡仍正常提醒（不误杀）

**依赖 / 风险**：只改查询过滤与退房标记，不动门锁侧；`checked_out_at` 为 NULL 的历史数据行为不变。
**待拍板**：无
