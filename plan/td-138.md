# TD-138 启动探测设备 + 加载动画 + 顶部四态 tag

**优先级** P1 · **状态** 已完成 · **来源** US-1106-40 · **模块** 工程与发布

**为什么做**：原来 `info` 为 null 时顶栏什么都不显示，用户看不出「在探测」还是「没设备」。

**拍板**：先毫秒级快判给 tag 定型，后台再真探测串口覆盖结果（避免每次启动慢 2–8 秒）。

**改动点（`App.tsx`）**
1. 新增 `infoLoading`（初值 true）与 `deviceOk: boolean | null`。
2. `refreshInfo()`：`appInfo()` 成功 → 快判 `driverSha256 !== null && sdkSource !== null` → 后台
   `probePorts()`（catch 住）任一 `available` 即覆盖为可用 → `finally` 结束 loading；异常置 `deviceOk=false`。
3. 顶栏 tag 四态：`探测设备中…`（LoadingOutlined 转圈）/ `模拟设备`（橙）/ `未探测到设备`（橙 + Tooltip
   排查提示）/ `设备就绪`（绿）。

**验收标准**
- [x] 启动瞬间显示转圈「探测设备中…」，不再空白
- [x] 探测到可用端口 → 「设备就绪」；全不可用 → 「未探测到设备」（带排查 Tooltip）
- [x] `OCW_SIM=1` 时仍显示「模拟设备」，不被覆盖
- [x] `pnpm exec tsc --noEmit` 通过

**依赖 / 风险**：`probePorts` 会逐个打开 COM1–COM8，可能被原门锁软件占用而超时——已放后台且 catch，不影响界面；
真探测结果会覆盖快判，若用户刚切换串口需等下一次 `refreshInfo`。
