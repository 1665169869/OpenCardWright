# 智能门锁 TEMIC 卡 —— 逆向成果与发卡 SDK

对「智能门锁管理软件（LOCK_V8 / V8.9）」所用 125 kHz TEMIC 卡的完整逆向，
以及一个**不依赖原软件、不依赖加密狗**的独立发卡 SDK。

> 原软件厂家已倒闭，本目录即为替代方案。

---

## 一、能做与不能做

| 能 | 不能 |
|---|---|
| 发日租客卡（1~1095 天） | 发「应急码设置卡」「楼栋/楼层/应急/通道开门卡」（**无样本，格式未知**） |
| 发钟点客卡（1~62 小时） | 解释锁如何判定"钟点卡到期"（机制未最终验证） |
| 发总控卡、复位卡、清除卡、安装卡 | 绕过原软件的授权/加密狗（本方案本就无需授权） |
| 发退房钟点卡、校时卡 | 读写除 TEMIC 之外的卡（IC/M1/EM4305） |
| 读卡并解析卡内全部字段 | — |

## 三、快速开始

```bat
cd sdk

:: 读卡
PMSLockCard.exe read

:: 客卡
PMSLockCard.exe issue --room 220 --days 1
PMSLockCard.exe issue --room 220 --days 90        :: >63 天自动用月码
PMSLockCard.exe issue --room 220 --hours 3

:: 总控卡（小时编码与客卡不同）
PMSLockCard.exe issue --type master --hours 2

:: 管理卡
PMSLockCard.exe issue --type reset
PMSLockCard.exe issue --type clear
PMSLockCard.exe issue --type install --room 220
PMSLockCard.exe issue --type checkout --hour 12   :: 退房钟点卡
PMSLockCard.exe issue --type timesync              :: 校时卡（用当前时间）
PMSLockCard.exe issue --type timesync --room 15:30 :: 指定时间

:: 原样写任意 8 字节
PMSLockCard.exe issue --raw --p1 5BECF100 --p2 810147AB

:: 自检（不接硬件，纯字节比对 27 组原厂样本）
PMSLockCard.exe selftest
```

- `--port`：串口索引，`0`=COM1，`6`=COM7
- 退出码：`0` 成功 / `1` 参数 / `2` 驱动或串口 / `3` 无卡 / `4` 写入失败 / `5` 回读校验失败 / `6` 卡号无效 / `7` 不支持

## 四、卡内格式

```
页1 = 5B EC | ((序号 & 0x0F) << 4 | 低4位) | (序号 >> 4)
页2 = 时长码 | 卡号低字节 | 卡号高字节 | 0xAB
页3~7 = 00 00 00 00
```

**时长码**

| 卡型 | 小时 | 天 |
|---|---|---|
| 客卡 | `0x40 \| (小时+1)` | `0x80 \| 天数`（≤63） |
| 总控卡 | `0x40 \| 小时` | `0x80 \| 天数`（≤63） |
| 长期（>63 天） | — | `0xC0 \| round(天数/31)` |

**管理卡**

| 卡 | 页1 | 页2 |
|---|---|---|
| 复位卡 | `5BEC0A00` | `00\|卡号低\|卡号高\|AB` |
| 清除卡 | `5BEC9BE5` | `C7\|卡号低\|卡号高\|AB` |
| 安装卡 | `5BEC((序号<<4)\|0x0C)(序号>>4)` | `46F20001` |
| 退房钟点卡 | `5BEC7B<小时>` | `FF\|卡号低\|卡号高\|AB` |
| 校时卡 | `5BEC<值低><值高>` | `14\|卡号低\|卡号高\|AB` |

校时卡：`值 = 16 × 当日分钟数 + 953`（只含时/分，不含日期）。

**序号**：来自数据库 `Kf_fh.Fqcbh`（房号可改名，序号不变）。现网对照见 `data\RoomIndex.ini`。

## 五、锁的规则（实测）

**卡号**——锁对**每种卡型**分别记住一张"当前有效卡"：

| 新卡号 | 结果 |
|---|---|
| 大于当前有效号 | 开门，并更新 |
| **等于**当前有效号 | 开门 |
| 小于当前有效号 | 拒绝 |

日租卡与钟点卡**互不影响**；写卡本身不改变锁内记录，**只有刷过才生效**。

**复位卡**：清空该房间的卡记录（高水位归零）→ 旧卡恢复可用，卡号用尽时有解。

**新锁初始化顺序**：

```
复位卡 → 清除卡 → 安装卡 → 校时卡
```

## 七、重要提示

1. **卡号要紧贴原软件序列**。`CardNo.state` 是本地计数器，不要跳到 `0x4700` 那种量级 ——
   同类型的软件卡会长期失效，直到刷复位卡或用软件追上（软件每秒约 +1/次发卡，追得很快）。
2. **超过 63 天必须用月码** `0xC0|round(天数/31)`，不是 `0x80|天数`。
3. **总控卡的小时编码比客卡少 1**（`0x41` vs `0x42`），日租编码相同。
4. 身份信息（姓名/证件/单位编号）**不写进卡**，只存在数据库 —— 卡上永远只有 8 字节。
5. `1095 天`（3 年）的卡**刷一次会把房间有效卡顶到 3 年后**，测试时别拿去刷门。
6. 用 `config_parameter(0)`（明文）写卡；扰码模式会把读卡器留在特殊状态，需再调一次 `(0)` 恢复。

## 十二、卡号用尽与定期维护（**运维必读**）

### 12.1 空间与时间尺度

卡号是 **16 位**：`0x0000` ~ `0xFFFF`，共 **65,536** 个。

原软件按 +1 递增，实测约 **85 号/天**（日常使用强度），因此：

```
65536 ÷ 85 ≈ 770 天 ≈ 2 年 1 个月
```

### 12.2 溢出行为（**推断，未验证**）

软件到 `0xFFFF` 之后，最可能是**回绕到 `0x0000`**，然后 `0x0001`、`0x0002`…

但此时锁内的高水位还在 `0xFFxx` —— **新发的小号卡全部被拒**，全楼发卡失效。

> 从未实测过回绕（要 2 年才遇到一次），以上是按 16 位整数的常识推断。

### 12.3 处置流程

```
卡号接近 0xFFFF
      ↓
等它回绕（或确认已回绕）
      ↓
挑「空房时段」，逐把锁刷复位卡
      ↓
锁内卡记录清零（高水位 = 0）
      ↓
软件之后发的小号卡立刻恢复有效（0x0001 > 0 ✅）
```

**⚠️ 千万不要提前复位。**

如果在 `0xFF00` 时复位，之后软件继续涨到 `0xFFFF` 再回绕，锁的高水位又被抬到 `0xFFxx`，回绕时照样失效。
**必须在回绕之后做。**

### 12.4 复位的影响

| 影响 | 说明 |
|---|---|
| 该房间**所有旧卡立刻失效** | 包括在住客人的卡 |
| 只能挑**空房/退房后**做 | 否则把客人锁在门外 |
| 逐把锁单独刷 | 每把锁各记各的，N 把锁刷 N 次 |
| 一张复位卡可刷遍全楼 | 复位卡页1 固定 `5BEC0A00`，**不含房号** |
| 软件侧无需特殊设置 | 软件不记录锁的状态，只需按正常流程重新发卡 |

### 12.5 平时的监控

`PMSLockCard.exe read` 读任意一张卡，输出里的「卡号」就是当前水位。

建议运维定期（如每季度）看一眼：

| 当前号 | 动作 |
|---|---|
| < `0xE000` | 正常 |
| `0xE000` ~ `0xFF00` | 开始安排维护窗口 |
| 已回绕（出现 `0x00xx`） | **尽快做全楼复位** |

### 12.6 关于"挂失卡"

挂失卡我们抓到了格式（页2 首字节 `0x41`，分「客人挂失卡」和「总控挂失卡」两种），
但**未在锁上验证效果**，且只有一对样本，因此 **SDK 不提供**。

**客人丢卡的常规处理**：直接发一张新的同类卡（号码更大），刷一次门即可顶掉旧卡 ——
效果与挂失卡等价，不需要额外格式。
