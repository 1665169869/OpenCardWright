# OpenCardWright 使用手册

> 面向**前台与管理员**，不涉及构建与代码。开发/排障请看 `../README.md`，
> 每个版本改了什么看 `../../CHANGELOG.md`，未完成事项看 `../../plan/待办清单.md`。

---

## 1. 安装

1. 双击 `OpenCardWright_x.y.z_x64-setup.exe`，按提示安装。
2. 首次运行 Windows 可能弹 **SmartScreen**「Windows 已保护你的电脑」：
   点「更多信息」→「仍要运行」。这是因为安装包**未做代码签名**（需要付费证书），
   不是病毒提示。
3. 程序只允许开一个实例（串口是独占资源）。重复打开会把已有窗口叫到前台。

数据都在 `C:\ProgramData\OpenCardWright\`：

| 路径 | 内容 |
|---|---|
| `opencardwright.db` | 房间、发卡记录、账号、设置（**唯一重要的数据**） |
| `runtime\` | 设备程序与配置（`LockCard.ini`、`CardNo.state`） |
| `logs\` | 按天日志，最多 5 份 |
| `backups\` | 手动与自动备份 |
| `diagnostics\` | 诊断包 |

## 2. 首次使用

1. 打开程序 → 设置管理员密码（至少 8 位，需含字母与数字）。
2. 自动弹出**三步向导**：
   - **检查设备**：确认「真实设备 / 模拟设备」、驱动指纹；选串口（不确定就保持默认，之后可在 设置 → 设备 改）。
   - **运行自检**：40 项自检，全过才说明读写卡链路正常；失败可先跳过排查。
   - **导入房间**：选 CSV（`房号,序号,房型,楼层`，后三列可空）或 ini（`房号=序号`）。
3. 点「完成」或「跳过」。跳过后再想导入：**设置 → 房间**。
4. 房间页出现房号后，右键房间 →「发行房间门卡」即可发第一张卡。

> 向导只会弹一次（写 `onboardingDone`）。想重跑：设置 → 设备 →「重新运行向导」不存在，
> 直接清空 `onboardingDone` 这个设置项即可（管理员操作）。

## 3. 发卡

### 3.1 客卡（日租 / 钟点）

右键房间 →「发行房间门卡」：

- 选时长：日租 1–62 天（更长只能选固定档位 90/120/…/1095），钟点 1–62 小时。
- 「预计退房时刻」取「设置 → 退房钟点」（默认 12 点，可在设置页改），这里**只读展示**；
  日租卡写库到期时间也按「退房日（开卡日 + N 天）的该钟点」记，写进卡里的仍是「N 天」。
- 客人信息（姓名/证件等）**只存库、不写卡**，可留空。
- 「读取身份证」（可选）：把身份证放到**身份证读卡器**上，点按钮即自动填姓名/性别/民族/出生日期/住址/证件号。
  它连的是本机华视读卡服务（WebSocket 9001），与发卡用的读卡器不是同一个设备；读不到只提示，不影响手填。
- 点「发卡」，把卡放到读卡器上等结果。

> **门锁是从「首次刷卡」开始计时的**，不是从发卡时刻。卡里只有时长码，没有绝对到期时间。

### 3.2 长有效期卡（>62 天）

会弹红色警示并要求输入 **「顶高水位」** 才能发。原因：这种卡刷一次门，就把该房间的
"当前有效卡号"顶到几年后，之后正常卡号比它小会被锁当成旧卡**拒开**，
只能给全部门锁各刷一次**复位卡**才能恢复。

### 3.3 续住 / 换房 / 退房

| 操作 | 入口 | 说明 |
|---|---|---|
| 续住写卡 | 右键 → 续住写卡 | 天数默认「剩余 + 1」，写一张**新卡**（卡号更大，锁认） |
| 换房 | 右键 → 换房 | 先**读卡核对**（不是本房原卡会二次确认）→ 源房全部有效卡登记退房 → 自动打开目标房发卡表单并带入客人信息 |
| 持卡退房 | 右键 / 顶栏「读卡退房」 | 读卡核对后按卡号退房 |
| 无卡退房 | 右键 → 无卡退房 | 按房间关闭全部有效卡，不需要卡 |

> 换房后**旧卡仍能打开原房间的门**（房间序号写死在卡里），到期前请收回。
> 房态不会自动变，写完新卡请按实际改目标房房态。

## 4. 管理卡（风险最高的一节）

管理卡页只有管理员能进。**四类卡的后果完全不同**：

| 卡型 | 作用 | 风险 |
|---|---|---|
| **总控卡** | 可开全部门锁 | 丢了等于丢一把万能钥匙，必须登记领用人 |
| **复位卡** | 把某房间的"当前有效卡号"归零 | **会清空该房间的卡记录**，之后签发的卡重新从低位开始 |
| **清除卡** | 清空门锁内的卡数据 | 等同于把锁恢复出厂，谨慎 |
| **安装卡** | 把房间序号绑定到门锁 | 刷错房间要用清除卡纠正；安装卡**不占卡号** |
| **空白卡** | 把卡内 8 字节全部写 0（等于擦成空白卡） | 卡变废卡、锁当无效卡拒开；用于回收旧卡、现场销毁废卡 |

操作规范：

1. 发管理卡后**当场在对应门锁上刷一次**，确认生效。
2. 总控卡、复位卡、清除卡要写**领用记录**（谁、何时、哪张卡号）。
3. 水位页的「重置水位」只能在**给全部门锁刷过复位卡之后**做 —— 否则新卡号比锁里记的小，
   那些锁会直接拒开。

## 5. 记录与导出

- 顶栏「记录」页：**发卡记录**（按房号/卡号/卡型/日期筛选，展开看 28 字节原始数据与同卡历史）、
  **操作审计**（谁在什么时候做了什么）。
- 「导出 CSV」仅管理员可见：导出当前筛选结果，落盘到桌面（或下载目录），
  Excel 直接双击打开即可，中文不乱码。
- 前台能查记录但**不能导出**（导出含客人证件号）。

## 6. 备份与恢复

**设置 → 备份**：

| 功能 | 说明 |
|---|---|
| 立即备份 | 生成 `backups\ocw-<时间>.db`，单个文件，可拷到别的机器 |
| 自动备份 | 默认**每 60 分钟**一次，保留最近 24 份；只清理 `auto-*`，手动备份永不删 |
| 导入外部备份 | 选任意位置的 `.db`，校验通过后出现在列表里，再点该行「恢复」 |
| 恢复 | 覆盖当前房间/记录/账号；恢复前自动另存 `opencardwright.db.before-restore-*.bak` |

> **备份不含卡号计数器**（`runtime\CardNo.state`）。换机器时除了恢复数据库，
> 还要把这个文件一起拷过去，否则可能从旧卡号发卡、把已发卡"顶掉"。

## 7. 常见问题

**Q：发卡时报"串口被占用/握手失败"？**
串口被其它程序占用（原厂软件、串口调试助手）。关掉它们，或到 设置 → 设备 重新探测端口。
`LockCard.ini` 里的 `Port` 是 0 基索引（`Port=6` 表示 COM7）。

**Q：读卡读出来是乱码 / 显示"未知卡型"？**
驱动输出是 GBK，程序内部已解码；若仍异常，多半是驱动版本不对 —— 对照 设置 → 设备 里的驱动指纹。

**Q：日志里说"模拟设备"？**
没找到 `runtime\PMSLockCard.exe` 或设置了环境变量 `OCW_SIM`。模拟模式**不会真的写卡**，
只用于演示与培训。

**Q：为什么发卡成功但客人开不了门？**
三种常见原因：① 卡刷错了房间（序号不匹配）；② 该房水位被长有效期卡顶高，新卡号比锁里记的小；
③ 门锁电池低电量。先看「记录」页里这张卡的卡号与房号是否正确。

**Q：能同时开两个前台吗？**
不能。程序只允许单实例（串口独占）。多台电脑各自装、各自连读卡器是可以的，
但它们的数据是**各自独立的数据库**，不共享。

**Q：误删了房间怎么办？**
删除是逻辑删除（房间从图里消失，序号不释放）。用「新增房间」填**同一个序号**即可复活，
历史发卡记录都在。

**Q：点右上角关闭，为什么弹出「缩小到托盘还是退出」？**
程序默认**缩小到系统托盘**继续运行（到期提醒、自动备份都不受影响）：
- 「缩小到托盘（推荐）」：窗口消失，右下角通知区域多一个图标；**左键点该图标**即可恢复窗口，
  右键图标可「显示主窗口」或「退出程序」。
- 「退出程序」：真正关闭（下次开机要自己再启动）。
- 「取消」：什么都不做，继续使用。
误点了缩小又找不到窗口：再双击一次桌面的程序图标，窗口会被叫回前台。
