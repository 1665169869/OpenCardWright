## 2. 串口帧层

### 2.1 发送：`sub_100011B6(cmd, payload, len)`

```c
// 每帧发送前先清空接收缓冲
while (ReadFile(hCom, buf, 1, &n, 0) && n == 1) ;

buf[0] = 0x80;
buf[1] = cmd;
cs = cmd + 0x80;
if (system_flag & 1) {                 // 扰码模式
    for (i = 0; i < len; i++) {
        cs += payload[i];              // 校验用明文累加
        buf[i+2] = F(cs);              // 发送的是 F(累加和)
    }
} else {
    for (i = 0; i < len; i++) { buf[i+2] = payload[i]; cs += payload[i]; }
}
buf[len+2] = 0xFF - cs;                // 校验字节
buf[len+3] = 0x00;                     // 不发送
WriteFile(hCom, buf, len+3, ...);
```

- 帧 = `80 <cmd> <payload×len> <cs>`，**总长 len+3，无尾随 0x00**。
- `system_flag` 由 `config_parameter(N)` 设置：bit0 = 发送扰码，bit1 = 接收扰码。
  因此 `N=0` 明文、`N=3` 双向扰码。

### 2.2 扰码函数 F / F⁻¹（**实测 256/256 双向验证**）

```c
T2 = {7,12,8,10,1,15,9,4,14,6,11,0,5,2,13,3}
T3 = {0x40,0xA0,0x10,0x90,0x30,0xD0,0x50,0x80,0xC0,0x70,0xE0,0x60,0x00,0xF0,0x20,0xB0}

F(a) = T3[a>>4] + ( ( (T3[a>>4] >> 4) + T2[a & 0x0F] ) & 0x0F )

T2i = {11,4,13,15,7,12,9,0,2,6,3,10,1,14,8,5}
T3i = {0xC0,0x20,0xE0,0x40,0x00,0x60,0xB0,0x90,0x70,0x30,0x10,0xF0,0x80,0x50,0xA0,0xD0}

G(a) = T3i[a>>4] + T2i[ (a - (a >> 4)) & 0x0F ]
```

验证结果：对全部 256 个输入，`G(F(x)) == x` 且 `F(G(x)) == x`，0 例失配；
并用 DLL 内导出的 256 字节表 `cipher_table.txt` 全表比对，0 例失配。

### 2.3 接收：`sub_10001479(out, buf, expectLen)`

```
读 1 字节，必须 = 0x80
读 1 字节 = 状态码
状态码 0x00 → 载荷长度 = 调用者指定
       0x01 → 载荷长度 = 1（1 字节错误码）
       0x05 → 载荷长度 = 4（32 位值，例如卡 UID）
       0x0D → 载荷长度 = 1（无卡/读失败码）
       其它 → 返回 5（协议错误）
（若 system_flag & 2）逐字节去扰：out[i] = G(byte) - prev；prev = G(byte)
读校验字节；校验：cs + 0x80 + 状态码 + Σ载荷 == 0xFF，否则返回 5
```

### 2.4 读单字节：`sub_100013AD(buf, longTimeout)`

- 超时：普通 1000 ms，`longTimeout != 0` 时 2000 ms（轮询 `GetTickCount`）。
- 超时返回 2，成功返回 0。

### 2.5 配置：`config_parameter(param)`

```c
payload[0..1] = 0, 0;
payload[2] = 0xA5;
payload[3] = (param & 3) | baudCode;
cmd 0x00，4 字节；成功后 system_flag = param
```

| 波特率 | baudCode |
|---|---|
| 9600 | 0x00 |
| 14400 | 0x10 |
| 19200 | 0x20 |
| 28800 | 0x30 |
| 38400 | 0x40 |
| 57600 | 0x50 |
| 115200 | 0x60 |
| 375000 | 0x70 |

抓包对拍：`config_parameter(0)` → `80 00 00 00 A5 00 DA` ✅

## 3. 各函数详解

### 3.1 `te_cardset(a1, a2, a3, a4)` — cmd 0x14

```c
payload[0] = a2;
payload[1] = (a3 ? 1 : 0) | (a4 ? 2 : 0) | (a1 ? 0x80 : 0);
```

| 参数 | 作用 |
|---|---|
| a1 | 置 payload[1] bit7（**推断**：调试/强制标志） |
| a2 | 直接下发（**推断**：卡型/模式字节） |
| a3 | payload[1] bit0 |
| a4 | payload[1] bit1 |

发送后等应答（`sub_10001699`）。

### 3.2 `te_setup(a1, a2, a3, a4)` — cmd 0x16，写**配置字**

```c
payload[0] = a1 ? 0x80 : 0x00;
payload[1] = 0x06;                       // 固定
payload[2] = 0x10;                       // 固定
payload[3] = 0x01 | (a3 ? 0x40 : 0);
payload[4] = 0x10 | (a4 ? 0x08 : 0) | (a2 & 0x07);
```

### 3.3 `te_setuppwm(a1, a2, a3, a4, pwd)` — cmd 0x17，带密码写配置字

```c
payload[0] = a1 ? 0x80 : 0x00;
payload[1..4] = pwd[0..3];               // 4 字节写密码
payload[5] = 0x06;
payload[6] = 0x10;
payload[7] = 0x01 | (a3 ? 0x40 : 0);
payload[8] = 0x10 | (a4 ? 0x08 : 0) | (a2 & 0x07);
```

> **注意**：payload 的字段顺序是 `[标志][密码 4 字节][配置字 4 字节]`，
> 密码在 `[1..4]`、配置字在 `[5..8]`，`a2/a3/a4` 只影响 `[7]`、`[8]` 两位。
> **实测对拍**：`te_setuppwm(0, 2, 0, 1, "12000206")` → payload
> `00 12000206 06 10 01 1A`，与上式逐字节一致。

### 3.4 配置字位域（实证）

厂商默认调用 `(a1=0, a2=2, a3=0, a4=1)`，得到配置字 4 字节：

```
06  10  01  1A
```

| 字节 | 位 | 值 | 来源 |
|---|---|---|---|
| [0] | 全部 | `0x06` | 固定 |
| [1] | 全部 | `0x10` | 固定 |
| [2] | bit0 | `1` | 固定 |
| [2] | bit6 | `0` | `a3` |
| [3] | bit4 | `1` | 固定 |
| [3] | bit3 | `1` | `a4`（厂商传 1） |
| [3] | bit0-2 | `010` | `a2`（厂商传 2） |

【推断】`a2`（0~7）对应 T5557 的 3 位速率/分频选择，`a3` / `a4` 对应调制方式与
密码保护开关；**位位置是实测的，语义需对照 T5557 手册确认**。

### 3.5 `te_read(out)` / `te_read_asc(out)` — cmd 0x15

```c
Size = 29;
send(0x15, NULL, 0);
recv(&status, buf, 29);
if (status == 0x0D) return buf[0];      // 无卡/失败码
if (status != 0x00) return 4;
memcpy(out, buf, 29);                   // _asc 版本先转成 58 个 HEX 字符
return 0;
```

- 返回 **29 字节**：前 28 字节 = 7 页 × 4 字节卡片数据，第 29 字节为读卡器附加的状态/保留字节
  （现场卡片该字节恒为 `0x02`）。
- `_asc` 版本输出 58 个 ASCII 字符（两位一字节，大写）。

### 3.6 `te_write(a1, page, data4)` / `te_write_asc` — cmd 0x16

```c
payload[0] = (page & 0x0F) | (a1 ? 0x80 : 0);
payload[1..4] = data4;
```

- `page` 仅低 4 位有效（0~15）。
- `_asc` 版本 `data4` 是 8 个 HEX 字符。

### 3.7 `te_writepwm(a1, page, pwd4, data4)` / `te_writepwm_asc` — cmd 0x17

```c
payload[0] = (page & 0x0F) | (a1 ? 0x80 : 0);
payload[1..4] = pwd4;
payload[5..8] = data4;
```

> **重要**：payload 的字段顺序是 `[页][密码][数据]`，不是 `[页][数据][密码]`。
> 第三方最容易在这里搞反（我们早期就因此写不进去）。

### 3.8 `te_selectpage(page)` — cmd 0x1A

```c
payload[0] = page;
```

用于部分卡型的显式选页；本产品线的读写**不依赖**它（写命令自带页号）。

### 3.9 `te_wakeup(word4)` / `te_wakeup_asc` — cmd 0x18

```c
payload = word4;      // 4 字节，原样下发
```

用途：给卡发唤醒/低层命令字（**推断**：T5557 的 `ST` 序列或直接驱动字段）。

### 3.10 `te_cardstop()` — cmd 0x19

无载荷，关断射频场。判卡程序常用"关场后重读"来区分"真读到卡"和"读卡器缓存帧"。

### 3.11 `te_get_id_asc(buf)` — cmd 0x1F

```c
recv(&status, buf, 8);
if (status == 0x0D) return buf[0];
if (status != 0) return 4;
to_hex(8, buf);          // 16 个 HEX 字符
return 0;
```

返回读卡器硬件 ID（现场值 `4E57520492008A7F`）。

### 3.12 `Cal_Crc8(init, len, data)`

```c
for each byte b:
    for 8 bits:
        if ((crc ^ b) & 1) crc = (crc >> 1) ^ 0x8C;
        else               crc >>= 1;
        b >>= 1;
```

标准 CRC-8/反射，poly `0x8C`，可自定义初值。

## 4. 应答状态码（`sub_10001479` 第 2 字节）

| 状态 | 载荷 | 含义 |
|---|---|---|
| `0x00` | 调用者指定长度 | 成功 |
| `0x01` | 1 字节 | 失败，附 1 字节错误码（`te_*` 直接把它作为返回值） |
| `0x05` | 4 字节 | 4 字节数据（如卡 UID） |
| `0x0D` | 1 字节 | 无卡/读失败，返回该字节 |
| 其它 | — | 协议错误，返回 5 |

## 5. 原厂软件的实际用法（抓包对拍）

| 操作 | 调用 | 线上帧（明文，`config_parameter(0)`） |
|---|---|---|
| 初始化 | `config_parameter(0)` | `80 00 0000A500 DA` |
| 选卡 | `mif_selecard(5)` | `80 02 05 78` |
| 读卡 | `te_read_asc(buf)` | `80 15 6A` |
| 设写密码 | `te_setuppwm(0,2,0,1,"12000206")` | `80 17 00 12000206 0610011A 1D` |
| 写页 1 | `te_writepwm(0,1,"12000206",data)` | `80 17 01 12000206 <data4> cs` |
| 写页 2 | `te_writepwm(0,2,"12000206",data)` | `80 17 02 12000206 <data4> cs` |

补充实测结论：

1. **写密码恒为 `12000206`**：DLL 内部的高层助手（`sub_10005848` 等）把
   `0x12,0x00,0x02,0x06` 直接写死在栈上，说明这是全系统统一的 TEMIC 写密码。
2. `te_write`(0x16) 对空白卡**写不进去**，必须先用 `te_setuppwm` 建密码窗口，再 `te_writepwm`。
3. 写完立刻回读会读到旧值（读卡器/卡刷新延迟），需重开串口或等待约 1 秒。
4. 原厂软件每个操作后 `FreeLibrary` 卸载驱动，导致挂钩调试时补丁会被丢弃。

## 6. 返回码

| 码 | 来源 | 含义 |
|---|---|---|
| 0 | 全部 | 成功 |
| 1 | `sub_100011B6` / `config_parameter` | 串口写失败 / GetCommState 失败 |
| 2 | `sub_100013AD` | 读字节超时（1~2 秒） |
| 4 | `sub_10001479` / `te_read` | 状态码非预期 / 非 0x00/0x0D |
| 5 | `sub_10001479` | 校验失败 / 未知状态码 |
| 其它 | `te_*` | 直接透传状态码 0x0D 时的 1 字节错误码 |

## 7. 已知坑（实战总结）

| 坑 | 现象 | 原因 |
|---|---|---|
| 用 `config_parameter(3)` | 读得出、写不进 | 载荷被扰码，写命令的页/密码/数据全变 |
| `te_writepwm` 参数顺序搞反 | 返回 0 但卡不变 | 帧是 `[页][密码][数据]` |
| 写完立即读 | 读到旧值 | 需要 ~1 秒或重开串口 |
| 用 `te_write` 写空白卡 | 全部 ACK 但无效 | 空白卡需先 `te_setuppwm` |
| 直接调 `tem_*_sdk` | 返回 4 | 那是 16 字节 GUEST 格式，要求卡已格式化 |
