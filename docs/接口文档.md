## 2. 卡格式接口

### 2.1 8 字节有效数据

T5557 现场卡只有页1、页2 可写，页3–7 全 0；有效数据共 8 字节：

```
页1 = 5B EC | ((序号 & 0x0F) << 4 | 低4位) | (序号 >> 4)
页2 = 时长码 | 卡号低字节 | 卡号高字节 | 年月
```

- 页1[0..1] 固定 `5B EC`。
- 页1[2] 高 4 位 = 房间序号低 4 位；低 4 位 = 挂失/特殊位（见 §2.6）。
- 页1[3] = 房间序号高 4 位（序号 0–254）。
- 页2[1..2] = 16 位卡号，低字节在前。
- 页2[3] = 年月（见 §2.5）。

【实测】卡内字节与驱动 `te_read_asc` 返回的 28 字节一致；页3–7 写不进。

### 2.2 卡型判定

读卡侧先看页1、页2 的固定特征，再按时长码段分客卡：

| 判定顺序 | 条件 | 卡型 |
|---|---|---|
| 1 | 前 8 字节全 0，或页2 = `12 12 12 12` | 空白卡 / 已退房 |
| 2 | 页1[0..1] ≠ `5B EC` | 未知 |
| 3 | 页1[2..3] = `0A 00` | 复位卡 |
| 4 | 页1[2..3] = `9B E5` | 清除卡 |
| 5 | 页1[2..3] = `F0 FF` | 总控卡 |
| 6 | 页2[0]=`46` 且页2[3]=`01` | 安装卡（页1 携带房间序号） |
| 7 | 页1[2] = `7B` | 退房钟点设置卡（页1[3] = 钟点） |
| 8 | 页2[0] = `06` 或 `14` | 校时卡（`06` 明文；`14` 为旧卡兼容） |
| 9 | 页2[0] & `0xC0` = `0xC0` | 日租客卡（月数编码） |
| 10 | 页2[0] & `0xC0` = `0x40` | 钟点客卡（小时编码） |
| 11 | 页2[0] & `0x80` = `0x80` | 日租客卡（天数编码） |
| 12 | 其它 | 未知 |

【实测】日租客卡与钟点客卡同房、同卡号、同发卡时刻下，**唯一差异是页2[0]**
（日租 `0x81` vs 钟点 `0x44`）；页1、卡号、年月完全相同。卡型靠时长码段区分。

### 2.3 时长码

| 卡型 | 小时 | 天 |
|---|---|---|
| 客卡 | `0x40 \| (小时+1)` | `0x80 \| 天数`（1–63） |
| 总控卡 | `0x40 \| 小时` | `0x80 \| 天数`（1–63） |
| 超过 63 天 | — | `0xC0 \| round(天数 / 30)` |

- 月码按 **30 天/月**：90 天 → `0xC3`，360 天 → `0xCC`，1095 天 → `0xE4`（36 月）。
- 客卡小时编码比总控卡多 1（客卡多算一个退房小时）。
- 【实测】锁按日历月执行；31 天/月会少算约一个月（TD-145）。

### 2.4 卡号（时间戳编码）

```
16 位 = (日 & 0x1F) << 11 | (时 & 0x1F) << 6 | 小时内序号(0–62)
```

- 例：11 日 12 点、本小时第 53 张（seq=52）→ `0x5B34`。
- 满 63 张后进位到下一小时、序号归 0；跨日同理。
- 写卡按小端：页2[1] = 低字节、页2[2] = 高字节。
- **卡号不含年月**；跨月同一天同一小时同一序号会重复，需靠锁高水位/复位卡管理。
- 产品侧每次发卡用「时间 + 小时内序号」生成；CLI 也支持 `--serial` 显式指定。

【实测】`0x5B34` 解码为 11 日 12 点 seq 52；`NextStamp` 的 63 张进位/跨日进位均有自检向量。

### 2.5 年月（页2[3]）

```
高 4 位 = (年 − 2000) & 0x0F
低 4 位 = 月
```

还原：`年 = 2000 + 16 × ⌊(当前年 − 2000) / 16⌋ + 高4位`，**16 年一循环**。
2026-11 写 `0xAB`，2027-11 写 `0xBB`。

【实测】年月随发卡时刻变化，不是常量 `0xAB`。

### 2.6 挂失

客卡 `页1[2]` **低 4 位 = 1** 即挂失；正常为 0。挂失卡仍是客卡，刷一次门让同房同卡型的旧卡失效。

- 仅日租/钟点客卡有挂失语义。
- 管理卡（复位/清除/安装/总控/退房钟点）没有挂失位。
- 校时卡 `页1[2]` 的低 4 位是时间位域（恒为 9），**不能**当挂失，否则每张校时卡都会被误读成挂失卡。

【实测】挂失位格式已确认；锁端失效效果仍需现场按批次确认【待定】。

### 2.7 管理卡

| 卡型 | 页1 | 页2 |
|---|---|---|
| 总控卡 | `5B EC F0 FF` | `时长码 \| 卡号低 \| 卡号高 \| 年月` |
| 复位卡 | `5B EC 0A 00` | `00 \| 卡号低 \| 卡号高 \| 年月` |
| 清除卡 | `5B EC 9B E5` | `C7 \| 卡号低 \| 卡号高 \| 年月` |
| 安装卡 | `5B EC ((序号<<4)\|0x0C) (序号>>4)` | `46 F2 00 01`（固定，不含卡号） |
| 退房钟点卡 | `5B EC 7B <小时>` | `FF \| 卡号低 \| 卡号高 \| 年月` |
| 校时卡 | `5B EC p1[2] p1[3]` | `06 \| 卡号低 \| 卡号高 \| 年月` |

【实测】复位/清除/安装/退房钟点/总控字节与原厂样本一致；清除卡和安装卡的真实锁效果【待定】。

### 2.8 校时卡

页1 位域（2026-11-08 七组样本验证）：

```
p1[2] = 16 × (分 & 0x0F) + 9
p1[3] = (分 >> 4) + ((4 × 时) & 0x7C)
```

- 页2[0] = `0x06`（明文；IDA: `LOBYTE(v14[2]) = 6`）。
- 页2[1..2] = 卡号，页2[3] = 年月。
- 旧卡读到 `0x14` 时按校时卡兼容解析（历史加扰残留）。
- 早期按 `值 = 16 × 当日分钟数 + 953` 的拟合公式已废弃；只在个别样本下近似成立。

【实测】七组时/分样本逐字节一致；**是否真正校准锁 RTC【待定】**。

### 2.9 空白 / 已退房

- 空白卡：前 8 字节全 0。
- 已退房：页2 = `12 12 12 12`（产品退房写零/写标记后读回）。
- 读卡解析两种都识别为 `Blank`，不参与发卡/退房匹配。

## 3. 驱动接口 `LC32RFRW.dll`

### 3.1 调用约定

- 全部导出为 **`__stdcall`**，返回 `int`（0 = 成功）。
- 写卡前必须 `config_parameter(0)` 切明文；`(3)` 是双向扰码，会让写命令的页/密码/数据全部被扰码。
- 一个进程/实例对应一个串口；驱动内部串口参数 `Port` 是 0 基（0=COM1）。

### 3.2 `te_*` 导出表

| 导出 | 地址 | 协议命令 | 载荷长度 | 作用 |
|---|---|---|---|---|
| `te_cardset` | `0x100034C1` | `0x14` | 2 | 卡片初始化/模式设置 |
| `te_selectpage` | `0x10003DEF` | `0x1A` | 1 | 选页（本产品线不依赖） |
| `te_read` / `te_read_asc` | `0x10003994` / `0x10003A38` | `0x15` | 0 | 读整卡 29 字节 |
| `te_write` / `te_write_asc` | `0x10003AF4` / `0x10003B67` | `0x16` | 5 | 写单页（无密码） |
| `te_setup` | `0x10003551` | `0x16` | 5 | 写配置字（无密码） |
| `te_writepwm` / `te_writepwm_asc` | `0x10003BEB` / `0x10003C73` | `0x17` | 9 | 带密码写单页 |

`mif_*`（`mif_selecom`、`mif_shake`、`mif_selecard`、`mif_beep`、`mif_closecom` 等）是串口/选卡/蜂鸣层，
由 `SM_RW_Card` 的函数表调用，不在 `te_*` 表中展开。

### 3.3 串口帧

发送（`sub_100011B6`）：

```
buf[0] = 0x80
buf[1] = cmd
payload[i] 明文或 F(累加和)（由 system_flag bit0 决定）
buf[len+2] = 0xFF - cs        // cs = cmd + 0x80 + Σpayload（明文累加）
WriteFile(buf, len+3)          // 无尾随 0x00
```

- 帧总长 = `len + 3`。
- `system_flag` 由 `config_parameter(N)` 设置：bit0 = 发送扰码，bit1 = 接收扰码。

接收（`sub_10001479`）：

```
读 1 字节必须 = 0x80
读 1 字节 = 状态码
状态 0x00 → 载荷长度 = 调用者指定
     0x01 → 1 字节错误码
     0x05 → 4 字节值（如 UID）
     0x0D → 1 字节无卡/失败码
     其它 → 协议错误，返回 5
（system_flag & 2 时逐字节 G(byte) - prev 去扰）
校验：cs + 0x80 + 状态码 + Σ载荷 == 0xFF，否则返回 5
```

### 3.4 扰码 F / G

```c
T2  = {7,12,8,10,1,15,9,4,14,6,11,0,5,2,13,3}
T3  = {0x40,0xA0,0x10,0x90,0x30,0xD0,0x50,0x80,0xC0,0x70,0xE0,0x60,0x00,0xF0,0x20,0xB0}
F(a) = T3[a>>4] + (((T3[a>>4] >> 4) + T2[a & 0x0F]) & 0x0F)

T2i = {11,4,13,15,7,12,9,0,2,6,3,10,1,14,8,5}
T3i = {0xC0,0x20,0xE0,0x40,0x00,0x60,0xB0,0x90,0x70,0x30,0x10,0xF0,0x80,0x50,0xA0,0xD0}
G(a) = T3i[a>>4] + T2i[(a - (a >> 4)) & 0x0F]
```

【实测】256/256 输入满足 `G(F(x)) == x` 且 `F(G(x)) == x`，并与 DLL 内 256 字节表全表一致。

### 3.5 CRC-8

`Cal_Crc8(init, len, data)`：标准反射 CRC-8，poly `0x8C`，可自定义初值。
帧层的校验字节不是 CRC，而是「明文累加和取反」（见 §3.3）；CRC 用于卡数据/配置校验。

### 3.6 `config_parameter(param)`

```c
payload[0..1] = 0, 0;
payload[2] = 0xA5;
payload[3] = (param & 3) | baudCode;
cmd = 0x00, 4 字节; 成功后 system_flag = param;
```

| 波特率 | baudCode |
|---|---|
| 9600 | `0x00` |
| 14400 | `0x10` |
| 19200 | `0x20` |
| 28800 | `0x30` |
| 38400 | `0x40` |
| 57600 | `0x50` |
| 115200 | `0x60` |
| 375000 | `0x70` |

抓包对拍：`config_parameter(0)` → `80 00 00 00 A5 00 DA`。【实测】

### 3.7 应答状态码

| 状态 | 载荷 | 含义 |
|---|---|---|
| `0x00` | 调用者指定 | 成功 |
| `0x01` | 1 字节 | 失败，附错误码（`te_*` 直接返回该码） |
| `0x05` | 4 字节 | 4 字节值（如 UID） |
| `0x0D` | 1 字节 | 无卡/读失败，返回该字节 |
| 其它 | — | 协议错误，返回 5 |

### 3.8 驱动返回码

| 码 | 来源 | 含义 |
|---|---|---|
| 0 | 全部 | 成功 |
| 1 | 发送帧 / `config_parameter` | 串口写失败 / GetCommState 失败 |
| 2 | 读 1 字节 | 超时（普通 1000 ms / 长超时 2000 ms） |
| 4 | 接收帧 / `te_read` | 状态码非预期 |
| 5 | 接收帧 | 校验失败 / 未知状态码 |
| 其它 | `te_*` | 透传状态码 `0x0D` 的 1 字节错误码 |

### 4.4 TEMIC 写卡时序

```
mif_selecom(port, baud)
  → Sleep(100)
  → mif_shake()
       失败：config_parameter(devtype==31 ? 0 : 3) → mif_shake() → 内部复位 → mif_shake()
  → mif_selecard(5)                 // 5 = TEMIC
  → te_read_asc(buf)                // 读当前 29 字节
  → te_setuppwm_asc(0, 页数, 0, 1, 密码)
  → for attempt in 0..2:            // 最多 3 轮
        for page in 起..起+页数-1:
            te_writepwm_asc(0, page+1, 页数据hex, 密码)
        Sleep(delay)
        te_read_asc(buf)            // 回读
        if 回读 == 期望: break
  → 匹配：mif_beep(beepTimes)，return 0
     不匹配：return 10
```

- 写密码恒为 `12000206`，硬编码在 `SmartLock.dll`（文件偏移 `0x328C78`）。
- `te_write`(0x16) 对空白卡写不进；必须 `te_setuppwm` 建密码窗口后用 `te_writepwm`。
- 写完立刻回读可能拿到旧值；需等待约 1 秒或重试。

## 5. 集成接口

### 5.1 .NET（`PMSLockSDK.dll`，.NET 4.0 / x86）

### 5.2 COM（`PMSLockSDK.Com.dll`）

- ProgId：`PmsLockSdk.Reader`
- 注册（管理员，32 位）：`regasm.exe PMSLockSDK.Com.dll /tlb /codebase`
- 方法：`Open(driverDir, port)`、`Read()`、`IssueGuest(room, days)`、`LastMessage`、`LastCardNo`、`Close`

### 5.3 CLI（`PMSLockCard.exe`）

命令：

```
PMSLockCard.exe ports
PMSLockCard.exe read [--json]
PMSLockCard.exe selftest
PMSLockCard.exe issue [--type guest|day|hour|master|reset|clear|install|checkout|timesync|raw] ...
```

关键参数：

| 参数 | 说明 |
|---|---|
| `--room-index N` | 房间序号 1–254（推荐） |
| `--room 220` | 房号（`RoomIndex.ini` 反查） |
| `--days N` / `--hours N` | 有效期 |
| `--seq N` | 小时内序号 0–62 |
| `--datetime "YYYY-MM-DD HH:mm"` / `--at` | 发卡时刻（决定年月） |
| `--serial HEX` | 显式卡号（十六进制） |
| `--lost` | 挂失客卡 |
| `--hour N` | 退房钟点 |
| `--json` | JSON 输出 |
| `--port N` / `--dir` / `--ini` | 串口/驱动/配置覆盖 |

### 5.4 JSON 输出

```json
{"ok":true,"card":{"kind":"日租客卡","room":"220","roomIndex":15,"days":1,
 "hours":0,"cardNo":"0x4B83","isLost":false,"issueDay":9,"issueHour":14,
 "issueSeq":3,"cardYm":171,"raw":"5BECF00081834BAB0000..."}}
```

失败：`{"ok":false,"error":{"code":6,"msg":"卡号无效"}}`。

| 4 | 写卡失败 |
