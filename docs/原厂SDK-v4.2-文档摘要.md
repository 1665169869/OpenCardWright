## 1. 适用范围与包内容

【原厂文档】「此接口函数仅适应于 VX.X_C 版门锁管理软件」——即配合原厂门锁管理软件使用，不是独立发卡库。

| 文件 | 作用 |
|---|---|
| `LCRFRW_SDK.dll` | 接口主 DLL（139 KB，随包三份副本） |
| `HD_SID.dll` | 附带 DLL（文档未说明用途） |
| `GetLockID.exe` | 从门锁软件工作目录读取「房号 ↔ 门锁编号」对应表 → 生成 `LockID.ini` |

## 2. 核心机制（文档原文最要紧的三条）

【原厂文档】

1. **作业流水号** = 「日期时间中的**年月日时** + **1 小时内所发卡的序号**」；「每张卡的作业流水号务必保持唯一并且存档，它是开门查询的依据」。
2. **开门条件**：「卡中作业流水号必须**大于等于**门锁电路板中作业流水号，否则将导致开门失败」。
   > 这一条与我们逆向结论「每个房间 × 每种卡型各自维护高水位：大于→开并更新，等于→开，小于→拒」**完全一致**，属独立证据互证。
3. **挂失标志（gs）多卡规则**：「若一个房间同时发三张卡，**第一张卡对应挂失标志需置为 1，后两张该挂失标志位需置为 0**」。

## 3. 接口函数清单（`LCRFRW_SDK.dll`）

### 3.1 打开 / 关闭串口

```c
int mif_selecom(int com, int baud);
int mif_closecom(void);
```

- `com`：**0 = 串口一**（门锁软件里从 1 计数，接口从 0 计数）；USB 读写器一般 3–8
- `baud`：**固定 9600**
- 【原厂文档】读写卡完成后**必须**调用 `mif_closecom()` 释放串口

### 3.2 读卡

```c
int tem_readdoorcard_sdk(LPSTR BH, LPSTR buff, int p_nLockAP);     // 返回 10 字符门锁编号
int tem_readdatetime13_sdk(LPSTR p_SDT, LPSTR p_Unit, LPSTR p_Times,
                           LPSTR p_CheckOutHour, LPSTR p_OpenInner, int p_nLockAP);
int tem_readidcard_sdk(LPSTR buff);                                // 仅 ID 卡，返回 10 字符 ID
```

- `buff`（读门锁编号）：**10 字符**，前 8 位「年月日时」，后 2 位「一小时内发卡序号（**十六进制**）」
- `tem_readdatetime13_sdk` 返回：起始时间、时间单位、时间长度、退房钟点、是否允许开反锁
- 【原厂文档】读卡前**卡片必须已被门锁系统写过一次客人卡**，否则读卡失败

### 3.3 写卡（客人卡 / 所有开门卡）

```c
int tem_writedoorcard13_sdk(LPSTR BH, LPSTR fksj, int xh, int sjdw, int sjlength,
                            bool gs, int p_nLockAP, int tfzd, bool fs);
```

| 参数 | 含义 | 取值 / 备注 |
|---|---|---|
| `BH` | 门锁编号 | **10 字符**（如 `Abcd0001`），由门锁软件分配、**无规律**，不是房号 |
| `fksj` | 发卡时间 | `YYMMDDHH` 8 字符，如 2004-08-09 10 点 → `04080910` |
| `xh` | 一小时内发卡序号 | **0–62**；超过 62 则 `fksj` 小时 **+1**、序号归 0 |
| `sjdw` | 时间单位 | **0=小时、1=天、2=月、3=年**；其它值按「天」处理 |
| `sjlength` | 时间长度 | 1–63 小时 / 1–63 天 / 1–15 月 / 1–3 年 |
| `gs` | 是否挂失在用客人卡 | 1=挂失，0=不挂失（同房多卡见 §2 第 3 条） |
| `p_nLockAP` | 系统标识号 | 对应 `LockID.ini` 末尾 `LockAP=X`；非二级代理商模式填 0 |
| `tfzd` | 退房钟点 | **范围 11–18**；示例：13-01-01 08:00 发 1 天卡、钟点 13 → 有效期到 13-01-02 13:00 |
| `fs` | 是否允许开反锁 | 0=不允许，1=允许 |

- 【原厂文档】**钟点房的退房时间不受 `tfzd` 限制**，写钟点房卡时 `tfzd` 填 11–18 之间任意值即可

### 3.4 退房回收卡片（官方擦卡做法）

【原厂文档】客人退房时仍可调用写卡函数回收卡片，参数为：

```
BH = 实际门锁编号
fksj = "00000000"
xh = 0
sjdw = 0        (小时)
sjlength = 1
gs = 0
```

> **注意**：这是「作业流水号清零 + 1 小时时长」的组合，**不是把 8 字节全部写 0**。我们产品里的「空白卡」写的是全零，两者是否等效【文档未提】。

### 3.5 时钟卡（校时卡）

```c
int tem_readtimercard_sdk(LPSTR fksj, LPSTR lpTime, int p_nLockAP);
int tem_writetimercard_sdk(LPSTR fksj, int nXh, LPSTR lpTime, int p_nLockAP);
```

- `fksj`：发卡时间 `YYMMDDHH`
- `nXh`：一小时内序号 **0–63**（注意：写时钟卡是 63，写客人卡是 62）
- `lpTime`：要写入门锁的时钟，**10 字符 `YYMMDDHHMM`**（精确到分钟），如 `0408092052` = 2004-08-09 20:52
- 【原厂文档】「时钟中的年月日与流水号的年月日需相同」；且**必须在门锁管理软件中写过一次时钟卡**

### 3.6 总卡 / 栋卡 / 层卡

【原厂文档】制作方式与客人卡相同，**只是 `BH`（门锁编号）不同**：先用演示程序读出该卡的门锁编号存库，再作为 `BH` 调 `tem_writedoorcard_sdk()`。

> 文档这里函数名写作 `tem_writedoorcard_sdk()`（无 `13`），与 §3.3 的 `tem_writedoorcard13_sdk` 并列出现，应为同一函数的不同版本名【推断】。

## 4. 房号 ↔ 门锁编号对照（`LockID.ini`）

【原厂文档】

1. 把 `GetLockID.exe` 拷到**门锁软件工作目录**下运行，选择门锁软件版本号 → 点「获取」
2. 生成 `LockID.ini`：**左边房号，右边门锁编号**
3. 末尾 `LockAP=X` 中的 X 即 `p_nLockAP` 参数
4. 备选办法：在门锁软件里对每个房号写一遍客人卡，再逐张读出门锁编号，自建对照表

文档还给了对照表样例：`Abcd0001→101`、`Efgh0002→102`、`Acda0003→201`、`Bded0004→202`，并强调**门锁编号看不出规律、由门锁软件分配**。

## 5. 授权流程

【原厂文档】

1. 运行 `SDKAuth.exe`
2. 向酒店索要**门锁授权卡**，放到读卡器上 → 读卡 → 得到信息码
3. 把信息码发给门锁供应商换取**接口专用授权码** → 输入 → 确认授权
4. 未授权时读写卡返回 **128**；输入门锁软件自己的授权码**无效**

## 7. 发卡原则与注意事项（原文要点）

1. **所有客人卡都必须在门锁软件系统中写过一遍**
2. **发卡原则**：开门卡在酒店管理系统发行；**其他管理类卡片（总卡/栋卡/层卡/时钟卡）均需在门锁软件系统发行**
3. **禁止多个门锁软件在不同卡片之间串发**
4. 正式开通前建议**收回所有卡片 → 发一张复位卡把门锁数据复位 → 再开始发卡**
5. **计算机时间不能乱**，否则可能开门失败
6. 客人卡被门锁自身注销/回收后，**须再发行一次客人卡**，否则接口读写卡失败
7. 读写卡完成后必须 `mif_closecom()` 释放串口

## 9. 与我们现有结论的关系（一句话）

- **互证**：作业流水号「大于等于」规则、小时序号唯一性、串口号从 0 起、9600 固定波特率
- **需要修正 / 待验证**：`tfzd` 官方范围是 **11–18**（我们允许 0–23）；官方「擦卡」是 `fksj=00000000 + sjdw=0 + sjlength=1`（我们写全零）
- **原厂没有能力对应**：安装卡、清除卡、房间序号绑定、长有效期档位——这些是我们的扩展，原厂包无法背书
