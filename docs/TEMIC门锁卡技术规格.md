# TEMIC 智能门锁卡 技术规格

> 对象：`D:\Program Files\智能门锁管理软件`（AppVer=LOCK_V8，LockSoftVer=V8.9，LockVer=V8）
> 卡型：125 kHz TEMIC（T5557/T5567 类），7 页 × 4 字节
> 读卡器：CH340 USB 转串口 + LC 系列发卡器
> 文档状态：**交付版**（2026-11-10 重写，清理已废止结论）。
> 证据标注：**【实测】**=有抓包/联机证据；**【推断】**=由证据归纳但未穷尽；**【待定】**=机制未证实。

> **核心模型（先看这一条）**
>
> **除安装卡外，所有卡（客卡、钟点卡、总控卡、复位卡、清除卡、退房钟点卡、校时卡）都基于
> 作业流水号 `YYMMDDHHII`**：页1 区分卡型 / 房间，页2[0] 是时长码，页2[1..2] 是流水号的
> `DDHHII` 段，页2[3] 是 `YYMM` 段。
>
> **安装卡是唯一例外**：只写房间序号，页2 固定 `46 F2 00 01`，不含作业流水号。

---

## 1. 结论摘要

1. 本软件的 TEMIC 卡**不是**用驱动里的 `tem_*_sdk` 写的。原软件只用驱动的**底层页读写**
   （`te_read` / `te_setuppwm` / `te_writepwm`），卡内是 **8 字节明文**私有格式。
2. **作业流水号 = `YYMMDDHHII`（10 位十进制）**：年 2 + 月 2 + 日 2 + 时 2 + 小时内序号 2。
   写卡时拆两处：`YYMM` → `页2[3]`，`DDHHII` → 16 位卡号。**除安装卡外所有卡型都带它。**
3. 卡内格式已完整解出：任意房号 / 天数 / 小时 / 总控 / 管理卡都能逐字节复刻，**实测可开门**。
4. 写卡必须用 `config_parameter(0)`（明文）；写密码 `12000206`；写完立即回读可能拿到旧值。
5. **已废止的旧结论**（不要再据此实现）：
   - 「锁按房间 × 卡型维护高水位、比较卡号大小」；
   - 「`页2[3]` 是固定常量 `AB`」；
   - 「`页1[2]` 低 4 位 = `天数 & 3 == 1`」（`LowNibble`，会让 1 天卡/钟点卡被误标挂失）；
   - 「月码按 31 天/月换算」（现按 **30 天/月**）；
   - 「校时卡页2 首字节是 `0x14`」（明文是 **`0x06`**，`0x14` 是加扰残留）。

## 2. 系统架构

```
NacreHis.exe                     门锁软件主程序（MFC）
  └─ SmartLock.dll               门锁业务模块（唯一导出 DoSmartLockDlg）
       └─ SM_RW_Card.dll         读写卡引擎（12 个 Do* 导出，动态 LoadLibrary 加载驱动）
            └─ LC32RFRW.dll      读卡器驱动（92 个导出，含 tem_*_sdk 高层函数）
                 └─ CH340 串口 → 发卡器 → TEMIC 卡
```

- `LC32RFRW.dll` 在 `IOServer\LC2000\` 与 `IOServer\LC2008\` 下是同一个文件（SHA-256 `f2f483e0…`）。
- 驱动导出分两类：
  - **底层**：`mif_*`、`tm_*`、`te_*`（T5557/5567）、`em4305_*`、`config_parameter`、`Cal_Crc8` 等；
  - **高层**：`tem_readdoorcard_sdk` / `tem_writedoorcard_sdk` / `tem_readtimercard_sdk` 等。
- 原软件走的是**底层**，所以第三方只要复刻 8 字节格式即可，**不需要也无法使用**高层 SDK。
- 各层调用链与 IDA 地址见 `发卡调用链逆向.md`。

## 3. 串口协议

> 帧层与 `te_*` 的逐个逆向（扰码算法、配置字位域、状态码）见 `T5557-5567函数逆向.md`。

### 3.1 帧格式

```
80 <cmd> <payload...> <cs>
长度 = 3 + payload 字节数
cs = 0xFF - (0x80 + cmd + Σpayload) & 0xFF
```

### 3.2 扰码开关（关键坑）

`config_parameter(N)`：

| N | 行为 |
|---|---|
| **0** | **明文**（原软件使用） |
| 3 | 载荷按换码表加扰（`sub_1000100C`，逆函数 `sub_100010E7`） |

同一写命令在 `N=0` 时是 `01DEADBEEF`，`N=3` 时是 `7B87192903`。**用错会「能读不能写」。**

### 3.3 常用命令

| cmd | 名称 | 说明 |
|---|---|---|
| 0x00 | config_parameter | 见上 |
| 0x02 | mif_selecard | 卡型：5 = TEMIC |
| 0x05 | mif_shake | 握手；首次常返回 2，需 `config_parameter` 后重试 |
| 0x0E | mif_beep | 蜂鸣 |
| 0x15 | te_read | 读 28 字节，返回 58 个 HEX 字符 |
| 0x16 | te_write | 写单页（无密码） |
| 0x17 | te_writepwm / te_setuppwm | 带密码写页 / 设置写密码 |

### 3.4 写卡时序（实测）

```
mif_selecom(port, 9600)
mif_shake()                       // 可能返回 2
config_parameter(0)
mif_shake()
mif_selecard(5)
te_read_asc(buf)                  // 读一次，判断卡状态
te_setuppwm(a1=0, a2=2, a3=0, a4=1, pwd="12000206")
te_writepwm(a1=0, page=1, pwd="12000206", data=P1)
te_writepwm(a1=0, page=2, pwd="12000206", data=P2)
mif_beep(2)
```

- `te_write`(0x16) 对空白卡**不可用**，必须走 `setuppwm + writepwm`。
- 写完**立刻回读会读到旧值**，须重新打开串口或等待约 1 秒后再读。

## 4. 卡内数据结构

```
页1:  5B  EC  [B2]  [B3]
页2:  [D0] [N_L] [N_H] [B7]
页3:  00 00 00 00    ← 原厂用于「开反锁」，T5557 卡写不进（见 4.5）
页4:  00 00 00 00    ← 原厂用于「退房钟点」，同样写不进
页5~7: 00 00 00 00
```

| 字节 | 构造式 | 含义 |
|---|---|---|
| `5B` `EC` | `Prefix0` / `Prefix1` | 固定前缀 |
| **`B2`** | `((序号 & 0x0F) << 4) \| low` | 高 4 位 = 房间序号低 4 位；低 4 位 = 挂失位（见 4.4） |
| **`B3`** | `(序号 >> 4) & 0xFF` | 房间序号高位；客卡通常 `00`，总控卡 `FF` |
| **`D0`** | `DurationDays()` / `DurationHours()` | 时长码（见 4.3） |
| **`N_L`** | `DDHHII & 0xFF` | 作业流水号低字节 |
| **`N_H`** | `(DDHHII >> 8) & 0xFF` | 作业流水号高字节（`N_H << 8 \| N_L`） |
| **`B7`** | `Suffix` | **年 + 月**（见 4.2；不是常量：2026-11=`AB`、2027-11=`BB`） |

### 4.1 房间序号

`B2` 高 4 位 + `B3` 拼成 12 位房间序号（业务用 1–254）：

```
序号 = ((B2 >> 4) << 4) | B3
```

房号 ↔ 序号来自数据库 `Kf_fh.Fqcbh`（见 §7），**房号本身不写卡**。

### 4.2 作业流水号 = `YYMMDDHHII`【实测】

**固定 10 位十进制**：

```
YY  MM  DD  HH  II
年  月  日  时  小时内序号（0–62）
例：2611081100 = 2026-11-08 11 时第 00 号
```

写进卡时拆成两段：

| 段 | 卡内位置 | 编码 |
|---|---|---|
| `YYMM` | `页2[3]` | 高 4 位 `(年−2000) & 0x0F`、低 4 位月（**16 年一循环**；2026-11=`AB`、2027-11=`BB`） |
| `DDHHII` | 16 位卡号 | `(日 & 0x1F) << 11 ｜ (时 & 0x1F) << 6 ｜ 序号(0–62)`，低字节在前 |

- 序号 0–62；满 63 张进位到下一小时、序号归 0。
- **除安装卡外，所有卡型都写这两段**（客卡、钟点、总控、复位、清除、退房钟点、校时）。
- 读卡时把两段拼回 10 位编号；空白卡没有 `YYMM`，只能显示 `DDHHII`。
- 发卡台与 SDK 都按发卡时刻生成完整编号；**不落库、不展示**（数据库列保留但停止读写）。

**6 组实测样本**（`RWCardDemo` 读数为准，证明两段拆分正确）：

| 卡字节 | `DDHHII` | `页2[3]` | 解出 | demo 读数 |
|---|---|---|---|---|
| `5BEC0100 8181238B` | `0x2381` | `8B` | 2024-11-04 14:01 | 24110414 ✅ |
| `5BEC0100 818123AB` | `0x2381` | `AB` | 2026-11-04 14:01 | 26110414 ✅ |
| `5BEC0100 810123AB` | `0x2301` | `AB` | 2026-11-04 12:01 | 26110412 ✅ |
| `5BEC0100 81015BAA` | `0x5B01` | `AA` | 2026-10-11 12:01 | 26101112 ✅ |
| `5BEC0000 81345BAA` | `0x345B` | `AA` | 2026-10-11 12:52 | 26101112 ✅ |
| `5BEC0000 81345AAA` | `0x345A` | `AA` | 2026-10-11 08:52 | 26101108 ✅ |

数据来源：用原厂 SDK（`tem_writedoorcard13_sdk`，patch 关扰码后）按指定时间 / 序号 /
挂失参数逐张写卡，再用 `RWCardDemo.exe` 读回核对。

> **历史说明**：早期曾用三张「同为 2026-11」的卡做对照，误判 `页2[3]` 不是日期字段。
> 那是样本选取错误——三张卡同月，`页2[3]` 当然相同；日期差异来自 `DDHHII`。
> 结论以本节的 6 组样本为准。

### 4.3 时长码 `D0`

| 卡类型 | 编码 | 样本 |
|---|---|---|
| 日租卡 | `0x80 ｜ 天数` | 1天→`81`、2天→`82`、5天→`85` |
| 钟点卡 | `0x40 ｜ (小时 + 1)` | 1h→`42`、3h→`44`、6h→`47`、62h→`7F` |
| 长期日租（>63 天） | `0xC0 ｜ 月数` | 90天→`C3`、120→`C4`、360→`CC`、1095→`E4` |

- 小时：客卡 1–62、总控卡 1–63（`0x7F` 为上限）。
- 天数：1–63 走 `0x80` 段；64 天以上走 `0xC0` 段。
- 高 2 位即单位：`0x40` 小时、`0x80` 天、`0xC0` 月。

**月数的换算：按 30 天/月**（锁按日历月执行）：

| 设定天数 | 字节 | 月数 |
|---|---|---|
| 90 | `C3` | 3 |
| 120 | `C4` | 4 |
| 360 | `CC` | 12 |
| 1095 | `E4` | 36 |

> 早期曾按 31 天/月推出 1095→`E3`（35 月），与锁的日历月执行不符，**已废止**。
> 90 / 150 / 210 这类非整月档位会被锁按整月执行，与设定天数有 ±2~3 天偏差。

⚠️ 超过 63 天只能选固定档位（90 / 120 / 150 / 180 / 210 / 240 … / 1095）。

### 4.4 挂失：`页1[2]` 低 4 位【实测】

原厂文档：「1 为取消在用的客人卡（挂失），0 为不取消」。

反编译 `tem_writedoorcard13_sdk`：

```c
LOBYTE(v51[1]) &= 0xF0u;          // 先清低 4 位
if ( a6 != 0 ) ++LOBYTE(v51[1]);  // gs=1 → 低 4 位 = 1
```

| 值 | 含义 |
|---|---|
| `0` | 正常卡 |
| `1` | 挂失卡（刷一次让同房同卡型旧卡失效） |

- 挂失位与天数 / 小时**无关**；旧记录里的 `天数 & 3 == 1` 是样本误读（`LowNibble` 已从代码删除）。
- 校时卡 `页1[2]` 低 4 位是**时间位域**（恒为 9），不适用本表。
- 原厂约定：同房三张卡时「第一张挂失位 = 1，后两张 = 0」——首卡负责作废旧卡。

### 4.5 页3 / 页4：退房钟点与开反锁【反编译 + 实测】

反编译 `tem_readdatetime13_sdk`：

```c
v13[0] = BYTE14(v9) & 0xE0;   // 退房钟点 = 卡数据第 15 字节高 3 位
v15 = sub_10002767(Str) + 11; // 3 位值 + 11 → 11~18 点
v20 = (BYTE9(v9) & 0x20) != 0; // 开反锁 = 卡数据第 10 字节 bit5
```

`te_read` 布局为 `页1 | 页2 | 页3 | 页4 | 页5 | 页6(配置)`，因此：

| 字段 | 卡内位置 | 编码 |
|---|---|---|
| 退房钟点 | 页4[2] 高 3 位 | `0x00`=11 … `0xE0`=18 |
| 开反锁 | 页3[1] bit5 | 1 = 允许 |

**T5557 卡写不进这两页**（2026-11-08 实测）：

| 写哪页 | 返回码 | 读回 |
|---|---|---|
| 页1 | 0 | ✅ 生效 |
| 页3 | 0 | ❌ 无变化 |
| 页4 | 0 | ❌ 无变化 |

**后果**：T5557 客卡自身不带退房钟点（`tfzd` 恒 0）；实际到期用的退房钟点来自**退房钟点卡**
写入的锁内设置（如 12 点），反锁同样只能由锁内状态控制。到期语义见 §11.1。

### 4.6 关扰码实验：能找到开关，但解决不了互通（2026-11-08）

定位并改掉两处 `config_parameter` 的模式参数：

| 地址 | 文件偏移 | 原字节 | 改后 | 位置 |
|---|---|---|---|---|
| `0x100038f4` | `0x38f4` | `6a 03` | `6a 00` | `mif_selecom` |
| `0x1000bfa8` | `0xbfa8` | `6a 03` | `6a 00` | `tem_readrfcardall_sdk` |

写出的字节确实变了，但仍是「未知卡型」——**原因是编码体系不同**：

| | 本方案（T5557） | 原厂 SDK 写的 |
|---|---|---|
| 寻址 | 房间序号 | 10 字符门锁编号（如 `CA68067C30`） |
| 编号 | 作业流水号 `YYMMDDHHII` | 同一概念，但布局不同 |
| 布局 | `5B EC \| 序号 \| 时长码 \| DDHHII \| YYMM` | 位串拼装后分块写入 |

**结论**：`RWCardDemo` 只能**读**我们的卡，**不能写**。

## 5. 卡型总表

### 5.1 客卡 / 钟点卡

```
页1 = 5B EC | ((序号 & 0x0F) << 4 | 挂失位) | (序号 >> 4)
页2 = 时长码 | DDHHII 低 | DDHHII 高 | YYMM
```

**日租与钟点唯一差异是 `页2[0]`**：`0x80|天数`（>63 天 `0xC0|月数`）vs `0x40|(小时+1)`。
页1、作业流水号、年月完全相同，卡型靠时长码段区分（2026-11-09 离线构包逐字节对比）。

### 5.2 总控卡

```
页1 = 5B EC F0 FF
页2 = 时长码 | DDHHII 低 | DDHHII 高 | YYMM
```

- 与客卡共用同一套**作业流水号**；房号位置固定为 `F0 FF`。
- 日租时长码与客卡相同；小时码**可能差 1**（总控 `0x40|小时` vs 客卡 `0x40|(小时+1)`）。

> **【待定】小时 +1 差异（TD-219）**：原厂抓包显示总控 1h=`41`、客卡 1h=`42`，
> 但尚未做「同参数客卡 vs 总控卡」对照与真锁闭环。复核方法见 `plan/td-219.md`；
> 结论出来前不要把 `+1` 当定论，也不要据此改 `DurationHours()`。

### 5.3 管理卡（除安装卡外都用作业流水号）

| 卡型 | 页1 | 页2 |
|---|---|---|
| 复位卡 | `5B EC 0A 00` | `00 ｜ DDHHII 低 ｜ 高 ｜ YYMM` |
| 清除卡 | `5B EC 9B E5` | `C7 ｜ DDHHII 低 ｜ 高 ｜ YYMM` |
| 退房钟点卡 | `5B EC 7B <退房小时>` | `FF ｜ DDHHII 低 ｜ 高 ｜ YYMM` |
| 校时卡 | `5B EC <值低> <值高>` | `06 ｜ DDHHII 低 ｜ 高 ｜ YYMM` |
| **安装卡（唯一例外）** | `5B EC ((序号 << 4) \| 0x0C) (序号 >> 4)` | `46 F2 00 01`（固定，**不含作业流水号**） |

**新锁初始化顺序（现场规程）**：复位卡 → 清除卡 → 安装卡 → 校时卡。

| 步骤 | 作用 |
|---|---|
| 复位卡 | 清空该房间的卡记录（实测：此前被拒的旧卡恢复可用） |
| 清除卡 | 清除门锁信息（房间绑定等；真实效果未验证） |
| 安装卡 | 写入门锁信息（绑定房间；真实效果未验证） |
| 校时卡 | 设定锁内时间基准 |

**校时卡编码 = `YYMMDDHHmm`（年月日时分）**（2026-11-08 位域解出 + 七组样本验证）：

```
YYMM  → 页2[3]（高 4 位年、低 4 位月）
DD    → 卡号日段
HH:mm → 页1[2..3] 位域：
        页1[2] = 16 × (分 & 0x0F) + 9
        页1[3] = (分 >> 4) + ((4 × 时) & 0x7C)
页2   = 06 ｜ DDHHII 低 ｜ 高 ｜ YYMM
```

- 校时卡**只记到分钟**：完整时间是 `YYMMDDHHmm`，没有秒。
- 卡号（`DDHHII`）里的序号段对校时卡**不承载时间含义**；分钟只出现在页1 位域。
- `页1[2]` 必须满足 `& 0x09 == 0x09`，否则读卡返回错误 4。

**示例** `2611011223`（2026-11-01 12:23）：

```
页1 = 5B EC 79 31
      79 = 16 × (23 & 0x0F) + 9
      31 = (23 >> 4) + ((4 × 12) & 0x7C)
页2 = 06 ｜ 卡号低 ｜ 卡号高 ｜ AB      （AB = 2026-11）
```

| 时间 | 页1（实测） | 校验 |
|---|---|---|
| 08:30 | `5BECE921` | `16×14+9=0xE9`；`1+4×8=0x21` |
| 12:00 | `5BEC0930` | `16×0+9=0x09`；`0+4×12=0x30` |
| 19:47 | `5BECF94E` | `16×15+9=0xF9`；`2+4×19=0x4E` |
| 16:35 | `5BEC3942` | `16×3+9=0x39`；`2+4×16=0x42` |

> 旧公式 `值 = 16 × 当日分钟数 + 953` **已废弃**：它只在 19:47 那组样本下近似成立，
> 不是真实编码；旧表里的「15:05 / 15:08…」是按该公式反算的，与位域解出的 04 / 07… 差 1 分钟。

**页2 首字节**：明文是 **`0x06`**（IDA：`LOBYTE(v14[2]) = 6`）。旧样本里的 `0x14` / `0x13`
是加扰模式留下的值，解析时两者都识别，**生成时必须写 `0x06`**。

**复位卡实测现象（2026-11-05）**：

| 测试 | 结果 |
|---|---|
| 刷复位卡 → 刷此前被拒的旧卡 | ✅ 能开 |
| 复位后刷任意同房卡 | ✅ 都能开 |
| 再刷一张更新的卡后，旧卡复刷 | ❌ 又失效 |

→ 复位卡清空该房间的卡记录；具体判定机制以锁固件为准（旧「高水位」解释已废止，见 §6）。

**安装卡说明**

## 6. 作业流水号与锁

## 11. 待验证项

> 均为不影响发卡功能的遗留问题，按需要再补。

### 11.1 到期语义（2026-11-10 现场确认）

> 证据等级：**【现场确认】**——由现场实际使用（刷退房钟点卡 + 校时卡后观察客卡失效）得出，
> 尚无对应抓包 / 字节样本；后续补样本时按 `抓包样本与验证记录.md` 登记。

**结论：到期时间由锁按卡内数据计算，不依赖「首次刷卡」时刻。**

| 卡型 | 到期计算 |
|---|---|
| 日租卡 | 卡内发卡日期 + N 天，落在**退房钟点**（锁内设置，如 12:00）→ 次日 12:00 |
| 钟点卡 | 卡内发卡时刻（小时级）+ N 小时 |

- 「发卡时间」来自作业流水号：`YYMM` 在 `页2[3]`、`DD` / `HH` 在 16 位卡号；卡内**没有分钟**。
- 退房钟点来自**退房钟点卡**：刷过该卡后，锁内退房钟点被设为卡内的小时（如 12）。
  卡内页4 的 `tfzd` 字段 T5557 写不进，所以不能靠客卡自带钟点（见 §4.5）。
- 锁内时间基准来自**校时卡**：没刷过校时卡，锁的时间可能不准，到期判定随之漂移。
- 旧说法「有效期从首次刷卡起算」「锁不会判过期」**不成立**，已删除；早期观察到
  「首刷后 3 小时 22 分仍能开」应解释为锁内时间 / 退房钟点未设置正确，
  而不是按首次刷卡计时。

**前置条件**（现场部署必须满足）：

1. 新锁初始化按顺序刷：复位卡 → 清除卡 → 安装卡 → **校时卡**；
2. 退房钟点与发卡台「设置 → 退房钟点」一致（默认 12），并用**退房钟点卡**写进锁；
3. 客卡的发卡时间必须是真实发卡时刻（作业流水号由 `cardno.rs` 按当前时间生成）。

## 14. 授权与合规（技术事实）

### 14.1 授权在哪里

| 模块 | 是否涉及授权 | 证据 |
|---|---|---|
| `KeyPro.dll` | **是** | 访问硬件加密狗、读写注册表、进程检查 |
| `SmartLock.dll`、`NacreHis.exe`、`HisServo.exe`、`DbDataTool.dll` 等 11 个模块 | 是（引用 KeyPro） | 二进制内含 `KeyPro` 字符串 |
| **`LC32RFRW.dll`（读卡器驱动）** | **否** | 只导入 KERNEL32 + USER32，无 ADVAPI32、无 `KeyPro` |

### 14.2 我们的方案为什么不触发授权

SDK 只调用 `LC32RFRW.dll` 的底层导出（`mif_selecom` / `te_read_asc` / `te_setuppwm_asc` /
`te_writepwm_asc` 等），**不加载 `KeyPro.dll`**、不调用 `SmartLock.dll` / `SM_RW_Card.dll` 的业务接口。

**实测**：无加密狗、无授权的机器上，通过 COM3 完成「读卡 → 设密码 → 写页1 → 写页2 → 回读校验」，
新进程回读一致。

### 14.3 风险与边界

1. **技术可行 ≠ 合同允许**：厂商可能主张调用接口需授权，属商务/法务判断。
2. **版本冻结**：结论只对 SHA-256 `F2F483E08BA8048FFD1C57E66CB35D9E32C1C1E280DC5F2FF100A5D881BCCBC0`
   的 `LC32RFRW.dll` 成立；驱动升级需重新评估。
3. **部署建议**：现场使用同版本驱动；升级前先跑 `selftest` 与一次真实读写。
